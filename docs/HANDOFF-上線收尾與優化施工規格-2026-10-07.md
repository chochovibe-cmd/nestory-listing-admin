## 2. V1.1 第一包：擷取＋生成統一流水線（上線後最高優先）

目標：店主「一直輸入，系統自己跑」。擷取佇列與生成佇列是同一條線，一起設計一次做。

- **擷取秒回**：`/api/import/product-page` 改成文字落稿（1–2s）即回應（外掛勾勾／toast 立即亮），圖片背景補抓。Vercel serverless 背景執行建議用 `waitUntil` 或既有 worker 模式（圖片/發布已有 worker 線），草稿加「圖片擷取中/已就緒」狀態。
- **AI 生成佇列**：
  - 進度改 draftId 關聯：`src/components/listing/generationProgress.ts` 目前只有 title、用 `draftMatchesGenerationProgressTitle` 比對（同名商品會認錯）。改為每 draftId 一個 job。
  - `/api/generate` 開始時把 DB 狀態寫成 processing，成功/失敗各自落庫；刷新頁面後狀態可靠。
  - 輸入表單按「加入生成佇列」即清空可輸下一件；失敗也離開表單變成佇列裡「需要處理」卡（目前失敗會卡住表單）。
  - 併發上限 1–2 件，逐件自動接續；失敗卡常駐顯示原因＋單件重試，不只靠 toast。
  - 既有半成品可改造：pending_input 草稿＋`DraftQueueList.tsx`（quick preview 底層叫 queue-strip）。
- **重生非阻塞**：`RegenCopyModal.tsx` busy 時四個關閉入口全鎖（35-36、58-59、75-76、116 行）。改成按下重生立即關窗，卡片顯示「↻ 重生中…」，完成後更新＋通知。

## 2.5 效能優化線（PERF，2026-10-08 併入；P0 稽核已由 GPT 完成）

GPT 已完成 READ-ONLY 效能稽核（P0 PASS，0 修改）。核心結論與指揮官修正後的施工安排：

**PERF P1A｜首載 JS 減肥（獨立小包，零行為改變）**
- `ResultCard.tsx`（~3043 行）開頭 import 的發布 Modal、CSV 預覽、重生視窗、Shopify Sync、生圖區等改 `next/dynamic` lazy load；`WorkspaceInputPanel.tsx`（120 KB）同理。

- 驗收：Vercel build 的 First Load JS 數字對比 795 KB 基準＋功能零改變（畫面、操作、資料結果完全一致）。
