# 文案排版規範（2026-07-18，Fable 夜工實作＋規則存檔）

> 依據：老闆 2026-07-18 凌晨指示（回饋 22 格式部分＋開場提醒＋Emoji 政策）。
> 本檔＝統一規則的唯一真相；後續 prompt／渲染改動不得偏離，改規則先改本檔。

## 1. 描述段落結構（◈ 制，取代 A/B/C/D/E 字母制）

儲存格式維持**純文字**（操作者在 textarea 審可讀中文），段落間空一行。

### 一般 tone（原有 6 tone，格式完全維持）

```
（開頭段，無標題：1-2 句破題，40 字內）

◈ 商品亮點
・重點詞：具體說明（3 條左右）

◈ 適合誰
・（2-3 條）

◈ 商品資訊
・（只寫有依據的；規則引擎的「➼ 適用情境」也插在這段）

◈ 購買提醒
・（依材質客製）
```

- 標題行固定「◈ 標題」；開頭段刻意**不加 ◈**（商品頁開頭是敘事句不是標題）——
  與老闆範本的差異點，老闆晨審如不同意改回全 ◈ 只需調 htmlFormat 一處。
- 舊字母制（歷史草稿）永久相容：解析與渲染都認得，無需回填資料。

### 潮巢導購版（COPY C1 專屬 description layout）

只有手動 tone `潮巢導購版` 使用以下閱讀節奏：

```
（痛點／慾望破題：無標題，1–2 句；不要先報商品名稱）

（商品介紹：無標題，2–4 句；商品事實 → 消費者意義）

◈ 收藏亮點
・短重點詞：具體商品事實＋好處／價值／使用情境（3–4 點為主）

◈ 為什麼會想帶回家
（1–2 個短段落：誰會喜歡、什麼情境會用、解決哪個小不滿足、為何比普通同類更有吸引力）

◈ 商品資訊
・（3–6 點皆可，只列有 evidence 的資訊；資訊不足時可整段省略）

◈ 購買提醒
・（1–3 點，依材質／商品類型客製）
```

核心寫法：

- 先找本商品真正相關的購買動機，再介紹商品；不要每篇套同一種「療癒／送禮／收藏」理由。
- 商品介紹與亮點都要盡量做 `feature → benefit`：不只說「有什麼」，也回答「所以對日常使用有什麼意義」。
- evidence pool 足夠時，描述正文＋收藏亮點合計至少努力使用 3 個只屬於本商品的具體資訊；evidence pool 不足 3 點時，不強迫湊。
- 商品資訊仍遵守既有 evidence hierarchy：尺寸、容量、重量、數量、材質、功能等沒有明確依據就少寫或不寫，禁止目測猜精確數字。
- 購買提醒沿用既有 material-specific safety：絨毛可提醒運送／收納壓痕與拍鬆恢復；壓克力避免碰撞刮傷；金屬避免長期潮濕；杯壺／日用品只寫有證據或安全常識支持的提醒。
- 語氣是潮巢自己的台灣繁中導購文案：幽默、可愛、有生活感、具體但不叫賣。
- 參考外部商品頁時只借「短破題 → 介紹 → 小標 → 條列 → 導購情境 → 資訊 → 提醒」的閱讀節奏；**不保存、不模仿、不照抄競品**任何文案句子，也不把競品文字當 few-shot example。

## 2. HTML 渲染規則（Shopify 邊界，htmlFormat.ts）

| 純文字 | HTML |
|---|---|
| 「◈ 標題」／舊「B｜商品亮點」 | `<h3><strong>◈ 標題</strong></h3>` |
| 舊「A｜開頭句…」 | 去前綴 → `<p>開頭句…</p>` |
| ・／➼ 條列行 | `<ul><li>` |
| 一般行 | `<p>`（同段內 `<br>`） |

心理學/轉換率備註：h3 視覺階層讓手機讀者 3 秒內掃到亮點區；
條列全部進真 `<ul>` 讓行距呼吸；開頭敘事句保持無標題直接進情感。

## 3. 銷售狀態開場提醒（saleStatusNotice.ts，只在 Shopify 邊界注入）

描述最前面一段斜體小提醒，溫暖小編語氣＋1 個 emoji：

| 銷售狀態 | 文案 |
|---|---|
| 海外代購（約14天） | 🕊️ 這件是海外代購商品，下單後大約 14 天抵達台灣——好東西值得等一下下，我們會幫你盯緊物流！ |
| 預購中 | ⏳ 這件目前開放預購中，到貨時程以頁面說明為準；有任何進度我們都會誠實回報，敬請耐心等牠回家。 |
| 台灣現貨 | 📦 台灣現貨，下單後約 1–3 個工作天出貨，很快就到你手上！ |
| 二手現貨 | 💛 這件是精心挑選的二手好物（品況見商品資訊），台灣現貨、約 1–3 個工作天出貨。 |

不寫回 DB；Showmore 端維持既有【交貨方式說明】結尾段，不重複。

## 4. Emoji 語氣政策

- **小編聊天口吻**：描述／FAQ 必須自然帶 emoji，沿用既有 1–2 個 contract。
- **可愛周邊輕鬆感**：描述／FAQ 鼓勵最多 1–2 個，不強制。
- **潮巢導購版**：description 0–2 個、FAQ 0–1 個，皆不強制；只有自然時才放，section heading 不放 emoji。
- **其他語氣一律禁用**。
- 所有 tone 的 enriched_title／seo_title／meta_description 禁 emoji。
- UI：`usesEmoji=true` 只表示該 tone 可能含 Emoji，不代表一定要有。

## 5. 共用解析器（sectionHeaders.ts）

段落標題的唯一解析點；scenarioKeywords（➼ 插入定位）、showmoreCopyRewrite
（段落拆解）、htmlFormat（渲染）三處共用，禁止各自寫 regex。

COPY C1 semantic aliases：

- `商品亮點`／`收藏亮點` → B
- `適合誰`／`為什麼會想帶回家` → C
- `商品資訊` → D
- `購買提醒` → E

因此潮巢導購版不 fork parser，舊 tone 與歷史草稿繼續相容。
