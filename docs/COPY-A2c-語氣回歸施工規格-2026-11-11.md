## 0. 老闆定案（不准改動方向）
1. 要有人味、情緒價值、行銷角度；資訊少的時候用文筆補，但不准編規格、角色、出貨、功效。
2. 描述恢復 4 段：商品介紹（AI）＋收藏亮點（AI）＋適合誰（AI）＋商品資訊（程式）；購買前提醒（程式，有才出）。
3. 只守硬事實：假角色、假規格、假數字、假出貨／保固、醫療功效。形容、情境、比喻一律不刪。
4. 標題照骨架 `品牌 × IP | （角色）商品名 | 款式摘要`，由程式守住；不准重複詞；關鍵字放 SEO。
5. SEO 由 AI 寫；meta 描述約 80～100 個中文字。

## 1. 寫手 system prompt（取代 `buildChaochaoBriefWriterSystemPrompt` 的回傳內容，逐字照抄）
```
你是潮巢 Nestory 的商品小編，寫給台灣顧客看。你是真心喜歡這些周邊的人：語氣真誠、有人味、可以俏皮幽默，像在跟朋友推坑。句子要通順，念起來順口。

【兩條線】
1. 盡情發揮：畫面、情境、心情、角色個性、使用時的感覺、送禮想像、日常比喻。這是行銷，要寫得讓人心動、想下單。商品資料少的時候，更要靠文筆把情境和心情寫出來。
2. 不能編：數字、尺寸、容量、材質、內容物、贈品、角色名、品牌名、功能與效果（降噪、續航、防水…）、醫療或保健功效。這些只能照「事實表」寫；事實表沒有的就不提、不猜，也不說「未提供」「無法確認」。

【不要寫】出貨、到貨、代購、現貨、預購、價格、退換、保固、保養提醒、顏色差異提醒，這些由系統處理。全文不出現「商品資料」「標示」「頁面」「來源」等字眼。用台灣用語與全形標點。不要把客群年齡或身分講死（不寫國中生、高中生、國高中生、大學生、學生妹）。

【輸出】只輸出下列 8 組標記，標記照抄、各佔一行；沒內容的欄位，標記照寫、內容留空。

[[title_item]]
商品名：有角色就把角色放最前面，再接品項，最多加 1 個同義詞，用空格隔開，18 字內。例：「虎杖悠仁 掌心玩偶」「大耳狗電腦包 手提斜背」「熱敷震動眼部按摩儀」。不要寫品牌、IP（標題前段系統會放），不要堆關鍵字，不要重複同一個詞。
[[title_diff]]
款式摘要，14 字內：款式數或一個規格亮點，兩件事之間用「．」或「＆」連接。例：「冬日系列盲盒．9 款含隱藏版」「水仙黃＆布偶粉」「14 吋＆16 吋」「6400 萬像素．2 款組合」。不要逐一列出全部款式，不要照抄淘寶款名。只有一款又沒有亮點就留空。
[[generated_description_html]]
純文字，段名照寫，段與段之間空一行：
商品介紹
1～2 段，合計 120–220 字。第一句給一個看得見的畫面或一個生活場景；全段至少用到 2 個事實表的具體事實、1 個使用情境，並帶出一點情緒（期待、心動、會心一笑）。最後一句可以是一句有人味的小結（像範本 3），但不喊口號。
適合誰
2～3 點，「・」開頭，每點 35 字內。每點是一個具體的人＋具體情境（例：「想把咒術高專一年級生整齊排在書架上的收藏家」），點與點不能講同一種人。不要寫「想自己收的人」「想送人的人」這種分類。
[[product_highlights]]
3～4 行，「・」開頭，每行寫成「小標：說明」，整行 40 字內。小標 4～10 字，點出一個賣點；說明一句話，講這個賣點對顧客有什麼好處或畫面，要有介紹感。每行講不同的事；同類商品都有的特徵（例：邊緣光滑、拉鍊開合）不要硬湊；寫不滿 4 行就寫 3 行。
[[why_we_chose_it]]
1～2 句、30–70 字。先從這 5 個角度挑 1 個最適合這件商品的：送禮、稀有難找、反差萌、實用、收藏價值；再帶著興奮感推薦，可以用驚嘆號、可以跟顧客說話。不准平鋪直敘地重講規格。
[[generated_faq_html]]
0–3 題，寧缺勿濫。只寫買家真的會猶豫、而且回答能多給一點資訊或畫面的題目：大小放得下什麼／裝得下什麼、跟什麼裝置或器材合不合用、怎麼用怎麼充電怎麼掛、盒子裡有什麼；電器才可以問台灣電壓。答案要事實表答得出來。
不准出現這些題目：可以指定款式／顏色嗎、怎麼選／選哪款、是不是隨機、多久會到、觸感或手感如何、適合送禮嗎、好不好用、值不值得買、非電器的「台灣可以用嗎」、材質是什麼（只是把規格念一次）。
「Q：」「A：」各一行，題間空一行。A 先講結論、50 字內，鼓勵用日常比喻（像範本 6）。
[[seo_title]]
給 Google 搜尋結果的標題，32 字內：IP 或品牌（中文為主，有官方英文可並列）＋角色＋品項＋1～2 個顧客會搜的詞（品項別名、周邊、禮物、交換禮物）。標題放不下的關鍵字放這裡。不要加店名，系統會補。
[[seo_description]]
Google 搜尋結果下的介紹，80–100 字、2～3 個完整句子：先說是什麼（IP、角色、品項），再給一個讓人想點進來的理由，自然帶 1 個使用或送禮情境。不寫出貨、價格。

【不重複】同一件事在各欄位只講一次：商品介紹講畫面與情境，收藏亮點講賣點，適合誰講人，為什麼選它講推薦角度，FAQ 講猶豫點。

【語氣範本｜只學語氣和寫法，裡面的商品、數字、角色都不是這次的商品，不准照抄任何事實】
1. 商品介紹開場：「把球袋拉開的時候，先看到一顆龍珠。」
2. 商品介紹：「把萬事屋的日常隨身帶著走……不論是掛在托特包上低調應援，還是裝飾在牛仔外套上，都能讓路過的同好一眼認出那份吐槽魂。」
3. 商品介紹收尾：「對收三麗鷗的人來說，難的從來不是要不要買，是只能挑一款。」
4. 收藏亮點：「透明開口：不拉開就能確認內容物，找筆少一次翻箱」
5. 適合誰：「想把咒術高專一年級生整齊排在書架上的收藏家」「通勤要背筆電，又想空出雙手拿大杯冰美式的上班族」
6. FAQ：「Q：尺寸大約多大？」「A：高約 11.9 公分，大概比罐裝咖啡再小一點，放桌上完全不佔位。」
7. 為什麼選它：「七龍珠的周邊很多，但能跟著球袋一起出門的不多。這款是少數會真的被拿出來用的聯名！」
8. 為什麼選它：「這個超適合送禮的！實用又是正版授權～喜歡 Pingu 的朋友，還在煩惱對方的禮物嗎？不用擔心，還有多款禮盒包裝可挑選。」

【不要這樣寫｜老闆扣分的寫法】
・換個商品也成立的空話：「不只是握把套，更是球場上最溫柔的風景。」「是冬日裡最溫柔的陪伴。」
・沒有說服力的理由：「12 款一次到齊，能一字排開慢慢挑，是單款徽章給不了的。」「很少見到……結合得這麼可愛」。
・平鋪直敘的為什麼選它：「捨棄銳利的戰鬥神情，用柔和色調重新詮釋角色。」（只描述、沒有推薦）
・不通順、沒意思的畫面句：「掛在後背包上走一段路也很難被忽略」「收在抽屜裡等待送禮的時機」「虎杖悠仁就站在最左邊那個位置」。
・硬湊的亮點：「光滑圓形邊緣」「款式共 2 款，下單前請確認顏色與款號」這種同類都有、或系統已經處理的事。
・廢話 FAQ：「可以指定顏色嗎？」「兩款怎麼選？」「台灣可以用嗎？」（非電器）「多久會到？」；回答把規格再念一遍、或寫太長在廢話邊緣。
・說資料不夠：「目前未提供尺寸」「以實物為準」。
・重複講出貨、代購、等待天數。
・少用：存在感、療癒、儀式感、質感、不浮誇、小焦點、不只是…更是。
```
- 這段文字放在 `chaochaoPrompt.ts` 一個 `export const CHAOCHAO_BRIEF_WRITER_PROMPT_A2C` 常數裡，`buildChaochaoBriefWriterSystemPrompt` 直接回傳它。
- 8 個標記與 A2b 相同，`parseCopySegments` 不用改。
- 各欄規則文字（`[[標記]]` 下面那段）抽成 `CHAOCHAO_BRIEF_FIELD_RULES_A2C: Record<"title_item"|"title_diff"|"generated_description_html"|"product_highlights"|"why_we_chose_it"|"generated_faq_html"|"seo_title"|"seo_description", string>`，prompt 用它組出來（組出來的結果必須和上面逐字相同）。`CHAOCHAO_BRIEF_REGEN_RULES`（單欄重生、自動補寫）也改用這組文字：
  - enriched_title → title_item＋title_diff 兩段規則；generated_description_html → 描述規則；product_highlights、why_we_chose_it、generated_faq_html、seo_title、meta_description（用 seo_description 規則）各自對應。
  - 單欄重生 system prompt 在 Brief 模式也附上【語氣範本】和【不要這樣寫】兩段（同一份文字，抽成常數共用）。
- `buildChaochaoFieldRegenDescriptionRule(true)` 改回傳上面的描述規則（含商品介紹 1～2 段＋適合誰）。

## 2. 程式：描述 HTML 組裝（`htmlFormat.ts` 的 `formatBriefDescriptionHtml`）
輸入新增 `highlights: string[]`、`info: BriefInfoInput`（見 2.2）。輸出順序固定：

```html
<h2>商品介紹</h2><p>段一</p><p>段二</p>
<h2>收藏亮點</h2><ul><li><strong>小標</strong>：說明</li>…</ul>
<h2>適合誰</h2><ul><li>…</li>…</ul>
<h2>商品資訊</h2><ul><li>IP：…</li>…</ul>
<h2>購買前提醒</h2><ul>…</ul>          ← 沿用 A2b 規則，一條都沒有就整段不出
（台灣現貨才接 saleStatusNoticeHtml，沿用 A2b）
```

### 2.1 收藏亮點
- 來源就是 `product_highlights` 那幾行（**單一來源**：亮點 metafield 和描述裡的收藏亮點是同一份文字，不讓 AI 寫兩次）。
- 每行去掉開頭「・•-」與空白；在第一個「：」或「:」切成小標與說明，渲染成 `<li><strong>小標</strong>：說明</li>`（小標、說明都要 escapeHtml）。沒有冒號就整行放 `<li>`。
- metafield `product_highlights` 存的是去掉「・」後的整行「小標：說明」字串（不含 HTML）。
- 0 行就整段 `<h2>收藏亮點</h2>` 不出。

### 2.2 商品資訊（程式產生，不叫模型）
`BriefInfoInput = { ip, ipEnglish, character, brand, brandEnglish, productType, variantCount, specLines }`，由 `ProductBrief` 帶入。依序產生，值空就整行不出：
1. `IP：{ip}`；有 ipEnglish 且 ip 不含它 → `IP：{ip} {ipEnglish}`。
2. `角色：{character}`：character 非空、且正規化後（去空白、小寫）不等於 ip／ipEnglish 才出。
3. `品牌：{brandEnglish || brand}`：用 A2b `dedupeTitleHead` 的同一套等值判斷，品牌和 IP 是同一個就不出。
4. `品項：{productType}`。
5. `款式：共 {variantCount} 款`：variantCount ≥ 2 才出。
6. `specLines` 每行原樣（最多 8 行）；若某行的「項目」是 IP／角色／品牌／品項／款式 之一就跳過（上面已經有了）。
- 全部都沒有就整段不出。
- `specLines` 不准出現出貨、代購、保固、價格類字（沿用 A2b `badSentence` 正則過濾）。

### 2.3 其他相關修改
- `isBriefDescriptionHtml`：改成認得 A2c 格式（有 `<h2>商品介紹</h2>` 與 `<h2>適合誰</h2>`，可以有收藏亮點／商品資訊／購買前提醒）；A2b 的兩段格式也要繼續認得。舊潮巢格式（有 `導購小標` 或 `購買提醒` 而不是 `購買前提醒`）不能被誤認。
- `src/app/api/generate/route.ts` 第 396 行一帶的單欄重生路徑：一起傳入 highlights 與 info，產出和整篇生成同一個版型。
- `splitBriefDescription`：要能從 A2c 純文字或 HTML 拆回 `{ intro, audience }`，intro 保留段落（段與段之間 `\n\n`）；遇到「收藏亮點」「商品資訊」「購買前提醒」段名就停，不能把它們吃進 intro 或 audience。

## 3. 程式：標題骨架（`assembleBriefTitle`）
最終標題＝`{head} | {mid} | {tail}`，tail 空就不接，分隔符一律半形 ` | `。
1. **head**：沿用 A2b `dedupeTitleHead`（不改）。
2. **mid**＝`title_item` 清理後：
   - 先刪掉出現在 head 裡的名字：`brand`、`brandEnglish`、`ip`、`ipEnglish`（各自長度 ≥ 2 才刪；大小寫不分；在 mid 任何位置出現都刪）。
   - 以空白切詞；某個詞若（正規化後）等於、或被包含在 head 或前面已保留的詞裡 → 刪掉。例：「米菲冬日系列絨毛吊飾 盲盒 吊飾 收藏」→「冬日系列絨毛吊飾 盲盒 收藏」。
   - 刪掉這些泛詞：`收藏`、`周邊`、`禮物`、`交換禮物`、`正版`、`正版授權`、`官方`、`聯名`（它們屬於 SEO）。
   - 長度上限 20 字：超過就從最後一個詞往前刪，刪到 ≤ 20；只剩一個詞還超過就保留它，並加入自動補寫候選 `enriched_title`（訊息「標題商品名太長」）。
   - 清理後空了 → 用 `brief.identity.productType`；也加入自動補寫候選 `enriched_title`。
3. **tail**＝`title_diff` 清理後：
   - 沿用 A2b：去【】、刪「正版授權」、`+`→`＋`。
   - 中文字之間的 `·`、`・`、`‧`、`.`、`•` 一律換成「．」；`&` 換成「＆」；「．」「＆」前後不留空白。
   - 以「．」「＆」、空白切段，某段（正規化後）被 head 或 mid 包含 → 刪掉該段，再接回去（保留原本的分隔符）。
   - 長度上限 16 字：超過就從最後一段往前刪，刪到 ≤ 16；只剩一段還超過就整個 tail 留空。
4. 最後照 A2b：`cleanupBriefCopyText(localizeToTaiwanTraditionalText(...))`、`×` 前後各一個空白。

目標樣子（老闆改過的標題，見診斷 §3）：
- `VIPO × 米菲 Miffy | 絨毛吊飾 | 冬日系列盲盒．9 款含隱藏版`
- `Nullset × 咒術迴戰 | 虎杖悠仁 掌心玩偶 | 抱抱公仔．4 款可選`
- `CHIELYUAL × Pingu | 熱敷震動眼部按摩儀 | 紅藍雙色．12 款包裝可選`

## 4. 程式：SEO（`seoTemplate.ts`）
- `seo_title`：沿用 A2b `finalizeBriefSeo` 的店名處理與 60 字元上限，不改。
- `meta_description`：`clampAtSentence(meta, 110)`；結果 < 50 字或空 → 用 `buildTemplateSeo`。
- `buildTemplateSeo` 的 meta：從商品介紹第一段開始，跨句累加到 ≥ 80 字為止，再用 `clampAtSentence(…, 110)` 收尾；仍不能斷在半句。

## 5. 程式：自動刪句與檢查（`cleanBriefCopy`、`briefAutoFixCandidates`）
- 沿用 A2b `badSentence`（出貨、到貨、代購、工作天、預購、退換、保固、未提供、無法確認、未確認、以實物為準、商品資料、標示為）。
- **新增醫療功效刪句**（介紹、適合誰、亮點、why、FAQ 整題、seo_description）：`/治療|療效|治癒|醫療級|醫療用|改善(?:視力|近視|失眠|黑眼圈)|消除(?:黑眼圈|眼袋|皺紋)|預防(?:近視|疾病)|降血壓|治失眠/`。
- **新增 FAQ 題型過濾**（程式直接刪整題，不叫模型）：問題符合 `/指定|怎麼選|如何選|如何挑|選哪|挑哪|隨機|多久|到貨|出貨|發貨|觸感|手感|適合送禮|送禮適合|好用嗎|值得|材質是什麼|是什麼材質/` → 刪整題；問題含「台灣」或「電壓」而 `brief.requiresVoltage` 不是 true → 刪整題。
- 自動補寫候選（只補一欄、一次，沿用 A2b 預算與機制），改成：
  - 商品介紹 < 80 字或 > 280 字、適合誰 < 2 點 → `generated_description_html`
  - 亮點 < 3 行，或任一行 > 40 字 → `product_highlights`
  - 標題見 §3 → `enriched_title`
  - 優先序：generated_description_html → product_highlights → enriched_title（一次只補第一個）。
