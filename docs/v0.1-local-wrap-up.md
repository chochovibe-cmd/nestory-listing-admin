## Next.js Startup Fix

Observed issue:

- `next dev` stayed at `Starting...`.
- `next build` either stayed after the startup banner or later stalled at
  `Collecting build traces...`.

Root cause:

- The repo-local `.pnpm-store/` contains many package-store files.
- Next.js tracing and webpack watching were scanning local non-app directories
  that should not participate in app compilation or runtime tracing.

Fix:

- `next.config.mjs` excludes `.pnpm-store/` and the untracked branch-staging
  folder from output file tracing.
- `next.config.mjs` also ignores those folders for webpack watch.
- The branch-staging folder is represented with JS Unicode escapes in config so
  Windows shell codepages cannot corrupt the path string.

## Safety Boundaries

Keep these boundaries in place for v0.1:

- Do not commit `.env.local` or any real token.
- Do not print `.env.local` values in logs or reports.
- Keep `.codex-next-*.log` ignored.
- Leave the untracked branch-staging folder alone; it belongs to another task.
- Keep Shopify live publishing paused.
- Do not set `SHOPIFY_STORE_DOMAIN` or `SHOPIFY_ADMIN_ACCESS_TOKEN` until the
  next explicit Shopify test phase.
- Do not rerun the full Supabase runtime flow unless a later change touches
  runtime data flow or auth/storage behavior.
