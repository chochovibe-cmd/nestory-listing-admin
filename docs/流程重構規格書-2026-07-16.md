# 流程重構規格書（三站式產線）

> 作者：Fable 總指揮（2026-07-16）。依據：老闆實機測試回饋 17–20、36–46、50、52–54
> （原文見 `docs/實機測試回饋-2026-07-16.md`）。
> 性質：**包三施工藍圖**。工人不得偏離本規格自行發明；有矛盾停工回報。
> 本規格覆蓋範圍內與 Mockup 不同處，以本規格為準（實作後補差異備忘）。

---

## 0. 一句話目標

把「九宮格狀態籤」換成**三站式產線**：卡片沿「文案待審 → 圖片待審 → 完成待發布」
單向流動（可退回），每站只顯示該站的資訊和動作；發布/匯出只在最後一站；
發布紀錄頁升級為「終點站＋補救站」。

## 1. 三站總覽

```
[輸入區] ─生成→ ①文案待審區 ─核准(分流)→ ②圖片待審區 ─┬─(無生圖標記)→ ③完成待發布區 ─發布/匯出→ 發布紀錄
                     ↑退回(解鎖文案)                    └─(有生圖標記)→ 圖審佇列(生成中/待審) ─圖審通過→ ③
                                                          圖審拒絕/失敗 → 留在圖審標紅，可改標記重送或退回②
```

- 舊「全部/待輸入/文案待審/需修改/已核准/圖片未標記/失敗/已發布/已封存」九籤 → 廢除。
- 工作佇列只剩三站籤＋失敗燈（見 §6）；已發布/已封存退出工作區（去發布紀錄/商品庫找）。
- 「待輸入」（生成前的殘骸/進行中草稿）不佔籤：進站①前的卡片只出現在快速跳轉區（§7），
  並可批次勾選刪除（回饋 39）。

## 2. 狀態模型與遷移

### 2.1 新增 stage 概念（migration 只產檔）
`product_drafts.pipeline_stage`: `input | copy_review | image_review | ready | published | archived`
（或方案可證明用既有 status 完整映射則零遷移；工人方案裁決點 Q1）

### 2.2 既有狀態映射
| 舊 | 新 stage |
|---|---|
| 待輸入/生成中 | input |
| ready_for_review（文案待審）/ 需修改 | copy_review |
| approved（已核准） | image_review（歷史資料落此站） |
| csv_ready / draft_created / active_published | published |
| failed（文案生成失敗） | copy_review 的失敗燈（§6） |
| archived | archived |

### 2.3 image_status 語意分離（回饋 52，包一先修）
Vision 辨識狀態與圖片處理管線狀態分欄。本規格假設包一已完成分離；
圖審佇列只認「真的送過圖」的處理狀態。

## 3. 各站卡片規格（回饋 38）

### 站①文案待審
- 顯示：縮圖、標題、IP/角色/類型 tag、警告燈（§8）、AI 成本小字。
- 動作：**核准**（單件＋批次勾選）、重新生成（§4）、批次刪除。
- **不出現**：封存、送圖、發布、產生 CSV、價格編輯以外的匯出類按鈕（回饋 39）。
- 下方編輯區＝現有文案/定價/Tags/SEO 分頁（含快速狀態隨分頁切換，回饋 28）。
- 核准後文案鎖定（卡片顯示 🔒），流到站②。

### 站②圖片待審
- 顯示：縮圖、標題、圖片標記摘要（N 張保留/簡轉繁/去字/重生）、「📄 定稿預覽」小標
  （點開浮窗看鎖定的文案/tag/價格，唯讀）。**不顯示**價格編輯（回饋 38）。
- 下方編輯區＝**只有圖片標記**（主圖/詳情圖分頁籤，回饋 45；標記規格見 §5）。
- 動作：**審核**（＝分流器，回饋 54）：
  - 全部「保留原圖」→ 直接到站③；
  - 含生圖標記 → 進圖審佇列（顯示預估 AI 張數/成本後確認）；
  - 「退回修改文案」→ 回站①解鎖。
- 批次審核：勾選多件一鍵分流；混合批自動各走各的。

### 圖審頁（/review，站②的加工廠）
- 兩區：「排隊生成中」（可看佇列）／「生成完成待審」（滑桿對比）。
- 失敗卡：留原區標紅＋**顯示失敗原因**（processing_error/warnings 原文）＋
  一鍵重新生成（帶完整草稿欄位上下文）＋可改標記重送（回饋 50）。
- 圖審通過 → 卡片回站③；拒絕 → 退回站②重標。

### 站③完成待發布
- 顯示：成品縮圖、標題、售價（多款式顯示區間，回饋 49）、處理小標（詳情圖✓/簡轉繁✓）、
  「📄 完整預覽」小標（文案＋成品圖）。
- 動作：**發布/匯出（多選）**：API 上架、API 建草稿、Matrixify CSV、Showmore CSV 可同時勾選；
  只選一項時提醒「完成後卡片會離開佇列，要不要同時匯出其他格式？」（回饋 36）。
- 「退回改文案」（帶著已生成的圖回站①）／「退回改圖」（回站②重標）（回饋 43）。
- 發布完成 → 卡片離開佇列，進發布紀錄；商品自動歸檔（不需手動封存，回饋 38）。

## 4. 「重新生成」彈窗（取代退回修改，回饋 39）
- 站①卡片與編輯區各留一顆「↻ 重新生成」：彈窗含
  (a) 語氣重選（沿用輸入區六語氣）；(b) 修改方向/補充資訊 textarea（進 LLM prompt）；
  (c) 確認鈕顯示預估成本。
- 儲存按鈕：偵測到編輯才浮出「儲存此版本」；未存收合跳警告（回饋 39）。

## 5. 圖片標記系統改版（回饋 46＋規格圖語意修正）
- 選項：**保留原圖（預設）／簡轉繁（圖上簡體字重生為繁體）／去字／重生主圖**。
- 預設全部「保留原圖」＝不進生圖佇列、零成本；只有改掉的圖會排隊花錢。
- 「規格圖」不再是處理標記：表單上傳時標一次即可（沿用 B5 toggle），卡片端不重複標；
  規格圖處理完**照常上傳 Shopify 圖片區**（修正 D1 的 spec skip）。
- 詳情圖：輸入區加「保留上架」開關（預設關，Vision 照讀）；開啟者進站②的詳情圖分頁籤，可調順序。
- 每商品「生成詳情圖」開關（預設開、可批次關）＝AI 合成圖工程（另立包，本包先留開關＋誠實停用態）。

## 6. 失敗處理（每站都有去處）
- 文案生成失敗 → 卡片留站①、紅燈＋原因＋一鍵重生（回饋 50）；不再流浪到圖審。
- 圖片生成失敗 → 留圖審、紅燈＋原因（§3）。
- 發布失敗 → 進發布紀錄失敗分頁，勾選重試（回饋 37）。
- 各站籤旁顯示紅色失敗計數；零件數籤自動隱藏（回饋 18）。

## 7. 快速跳轉區＋手機動線（回饋 41、42）
- 桌機：輸入區生成鈕下方（Mockup「本次已送出」樣式）擴充為**各站掛件總覽**：
  依站分組的小標（含短日期），點擊跳到該卡。
- 手機：底部 tab 插入「審核」(站①②③合一頁、頂部三段切換)；生成完成自動跳站①；
  頂部大按鈕「＋繼續新增」回輸入區。
- 生成按鈕文案照 Mockup：「✦ 生成（規則引擎 → Vision → 文案串流 → 定價）」。

## 8. 警告分級（回饋 31、40）
| 級 | 例 | 行為 |
|---|---|---|
| 🔍 建議 | 缺使用情境、缺推薦標籤、含網搜資訊請核實 | 小圖示點開說明；不計入待確認、不擋 |
| ⚠ 待確認 | 欄位空、價格未算 | 黃字；不擋核准但顯示 |
| ⛔ 必修 | 資料庫缺 IP/角色、必填缺、每款式成本不齊（49） | 紅字；擋核准/分流 |

## 9. 發布紀錄合併頁（回饋 37、44）
分頁：**批次紀錄**（Mockup 批次卡＋處理小標「含生圖/原圖直發」）｜**失敗重試**（原因＋勾選重試）｜
**Shopify 草稿**（同步草稿列表、可轉正式發布）｜**已發布/封存**（輕量卡：圖+標題+分類；
最多 30 筆，更早用日期/關鍵字查詢，接商品庫搜尋）。
舊 `/drafts` 佇列頁：功能併入本頁後下線（結案 Grok 時期分歧）。

## 10. 匯出預覽雙模式（回饋 53＋Matrixify 同規格）
- Showmore 與 Matrixify 匯出預覽共用元件：預設**條列摘要**（每商品一行：標題/售價/紅黃燈），
  可切**表格模式**（CSV 欄位對照，審單件細節）。
- 錯誤白話；紅=擋下、黃=可續（沿用現有分級）。
- 站③以外不出現匯出入口。

## 11. Shopify 互動時機（Fable 裁定）
- 站①核准**不再**建 Shopify 草稿；一切 Shopify 寫入延到站③「發布/匯出」執行時。
- 好處：中途退回不會在 Shopify 留過期草稿；語意單純。
- 遷移：既有「已核准＝已建草稿」的歷史資料標記為 published（草稿模式），不回收。

## 12. 通知對齊
- D6 圖片批次完成通知深連結 → 圖審「生成完成待審」；發布批次完成 → 發布紀錄批次卡。

## 15. 追加定案（2026-07-17）
- **淘寶擷取路線 D 核准**：桌機 Chrome 擴充一鍵擷取為主；手機走「分享網址→收藏草稿→
  回桌機補抓」半套（PWA share target 或複製貼上）。立包時機：包一＋R1/R2 後（可與 R3 討論對調）。
- **IP 知識三層案（併入包五）**：
  1. IP→語氣對照表由 AI 對 ip_catalog 全量預分類（六語氣），老闆審表後入庫；
  2. 目錄內 IP 一次性建「背景資料包」（角色關係/名場面/粉絲梗/關鍵字）入庫，生成時帶入；
  3. 冷門 IP 生成時即時網搜（沿用 web_search_cache 底子），搜不到誠實中性寫法。
