## 3. 產品定案（不可忘）

### 3.1 架構

```text
輸入 → ①審文案 → ②標圖 ─┬─ 全保留 → ③待發布
                         └─ 有生圖標記 → 🏭生圖工廠（獨立 /review）→ ③
```

- **不是**第 4 站  
- 站②＝標圖／分流決策台；工廠＝排隊＋驗 AI 圖  
- 站名 **「標圖」覆寫**舊「圖片審核」（DB `pipeline_stage=image_review` 不改）

### 3.2 桌機／手機 IA

- 桌機：左上輸入、左下快速預覽、右結果卡  
- 手機新增：輸入｜快速預覽；審核：純結果；工廠 tab 短標「工廠」

### 3.3 避撞（每包強制）

禁止改：`src/lib/providers/**`、`src/lib/csv/**`、`src/app/api/**`、migrations、prompt／標題引擎  
除非老闆／Fable 另開白名單。

### 3.4 與 Fable

- 系統邏輯、文案品質、migration 歸 Fable  
- 畫面 IA／toast／卡片顯示歸 UIUX 計劃包  
- 計劃包 §1.3 有共管時程（tone、reason 等）——以當時 Fable 回覆為準，接續時可問老闆 Fable 是否又更新

## 4. 標準作業流程（SOP）

1. **工人**貼開工指令（`docs/UX-?工人開場指令-….md` 的 text 框）  
2. 工人交 **修法確認清單** → 指揮回 **「指揮放行」**（必要時拍板 2–4 點）  
3. 工人實作 + commit + typecheck + b15-probe  
4. 更新計劃包 §9 + 施工清單進度筆記  
5. **Claude 核畫面** → 通過才開下一包開工指令  
6. 指揮寫下一包 `docs/UX-?工人開場指令-日期.md` 並更新計劃包 §6／§9
