# AI 合成詳情圖規格書（回饋 47，2026-07-19，Fable 總指揮親寫）

> 老闆定案（2026-07-19）：每商品產 **1 張**詳情長圖，融合重要資訊，
> 取代不能直接上架的淘寶簡體詳情圖。產出走既有接口：站②「生成詳情圖」
> 開關（流程重構規格書 §94 預留）→ 生圖工廠佇列。
> 路線未定案：老闆傾向 B（全 AI 生圖）但要先看 A（模板合成）的呈現
> → **SYN-0 打樣包先行，樣張比稿後才定管線路線。**

## 1. 產出物定義

一張直式詳情長圖（建議寬 1080px，長度隨內容，Shopify 商品頁詳情用），
內容區塊（素材全部來自草稿既有資料，零額外輸入）：

| 區塊 | 資料來源 |
|---|---|
| 頭圖＋商品名 | 主圖（處理後優先）＋title_zh |
| 賣點三條 | product_highlights（P1 後已有） |
| 規格表 | spec_text／product_specs 中繼 |
| 尺寸/材質示意 | 規格欄位＋（可選）規格圖 |
| 正版/品牌區 | product_brand＋IP＋「潮巢嚴選正版」 |
| 購買提醒 | 描述的 ◈ 購買提醒段 |

風格：跟隨現站設計語言（globals.css tokens 的色彩／字體氣質），
不是照抄淘寶版型。

## 2. 兩條路線（打樣比稿）

**路線 A｜模板合成**：HTML/CSS 版型 → server 端渲染成圖（或 sharp/canvas
排版）。文字 100% 清晰、風格穩定、每張成本≈0、改版型即全店統一。
AI 的參與在上游（文案已是 AI 生成），排版本身不呼叫生圖模型。

**路線 B｜AI 生圖**：以商品照＋文案要點餵生圖模型（OPENAI_IMAGE 既有
管線）直接產整張詳情圖。氛圍感強，但：中文字易亂碼、每張有成本、
同店風格不穩、資訊準確性不可保證（模型可能改寫規格數字＝誠實風險）。

**預期落點（打樣驗證）**：混合──文字資訊區塊用 A 保證正確清晰，
頭圖/背景氛圍可用 B 生成的素材墊底。

## 3. 分包

| 包 | 內容 | 驗收 |
|---|---|---|
| SYN-0 打樣 | 挑 2 件真商品（1 絨毛＋1 3C），A/B 兩路線各出 1 張樣張（B 可 2 版本），共 4–6 張圖檔交老闆比稿；附每張成本與產出時間 | 老闆挑方向（可挑混合） |
| SYN-1 管線 | 依定案路線實作：站②開關 → 生圖工廠佇列 → 合成 → 存 product_images(generated_detail) → 圖審驗貨 → 隨發布上架 | 全鏈真跑一件 |
| SYN-2 版型迭代 | 老闆用截圖＋一句話累積修版型（BX-P 模式） | 持續 |

## 4. 鐵則
- 規格數字只准從草稿欄位取，禁止生圖模型自行改寫（B 路線的文字若不可控，該區塊強制走 A）
- 產出存 `product_images.image_type='generated_detail'`（既有型別）進圖審雙迴路，不直接上架
- 詳情圖上架語意遵回饋 45 開關（保留上架/不上架）
- 打樣階段憑感覺挑即可；管線階段才談成本上限與批次
