## 已確認的問題與處理

1. CC-6 的篇幅參數未影響潮巢提示詞。本包讓正文長度、亮點、人群與 FAQ 題數回應精簡／標準／詳細；單欄重生只接本欄規則。
2. 搜尋原摘錄從第一個規格命中句起取，可能跳過前段造型，也可能忽略後段用途。本包用原有每來源 400 字額度，兼顧身分／造型、規格／用途，依來源順序輸出並去重。快取版本改為 adv8editorial1。
3. CC-6 已有置前聲音樣板，單純再搬樣板不是新改善。本包增加欄位任務與具體微型例句，整理重複指令，採正面引導。
4. Owner 最新標題定案是品牌 × IP，品牌英文優先。共用 prompt 和程式組裝一起改，多字英文品牌如 TOP TOY 保留完整。

3000 token 上限不是已證明的既有品質問題。本包保留上限與模型，不增加正常生成的模型呼叫次數、搜尋深度、搜尋次數或額外審稿步驟。輸出較豐富仍可能增加輸出 token 與等待時間，實際速度不能只靠架構保證。

## 各欄設計

| 欄位 | 寫作任務 |
|---|---|
| 商品標題 | 品牌 × IP中文＋英文，再接精準品項與有用差異；沒有品牌就只呈現 IP |
| 商品介紹 | 從可見造型進入生活画面，用短句寫出溫暖與輕幽默 |
| 收藏亮點 | 特點＋對買家的意義，提供不同角度 |
| 適合誰 | 具體的人與場合，如通勤掛包、角色收藏、送朋友 |
| 商品資訊／spec | 收齊可靠規格與款式差異，讓其他段落能輕快閱讀 |
| 購買提醒 | 說明適用的選款、照顧或等待條件 |
| 為什麼巢巢選它 | 一個具體選品觀察＋收藏或日常價值 |
| product_highlights | 可掃讀的 3–5 條不同特色 |
| FAQ | 先答實際問題，再補一點有用細節；每題單獨閱讀也清楚 |
| SEO 標題 | 常用商品名稱、IP／角色、精準品項、辨識差異 |
| SEO 描述 | 1–2 句寫身分、特色、適用情境 |
| 偵測／SKU | 維持結構資料與規則引擎職責 |

SEO 在正文與各欄自然分配正確名稱和辨識詞。此處改善文字搜尋辨識度，不代表已完成網站排名、索引、結構化資料或搜尋流量驗證。

## 事實與創作如何共存

不用模型自稱的 85%／90% 作為商品規格門檻。尺寸、材質、授權、限定等具體承諾以本款資料支持；造型觀察、情境、比喻可自然延伸。像「替通勤包添一小塊晴天」能放開寫，並不需要虛構規格來增加人味。外部素材仍作為資料，不作為指令。
