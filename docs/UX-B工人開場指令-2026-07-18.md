【T6】站籤常駐三站＋計數；失敗獨立有才顯（優先，改動集中、擋 IA）
────────
現況問題：
- StageFilterPills 在 count===0 時隱藏站籤 → 新手不知道有三佇列
- 文案仍可能是「文案審核／圖片審核／完成待發布」→ 對齊 §2.2
- 失敗目前掛在各站小紅字，未成獨立「有才出現」的失敗籤

定案 UI：
1. 三站**永遠顯示**（即使 0）：
   - ① 審文案（copy_review）
   - ② 標圖（image_review）← 覆寫「圖片審核」
   - ③ 待發布（ready）
2. 每籤顯示件數；0 也顯示「0」
3. **失敗籤**：合計 fail.copy_review + fail.image_review（+ 若有 fail.ready）> 0 才顯示
   - 標籤：⚠ 失敗（或「失敗」）
   - 點選後列表只顯示「該站失敗燈為真」的草稿（用既有 isCopyFail／image_status failed 語意，
     可在 stationFilter 或 DraftResultsPanel 加 filterFailDrafts 純函式；不改 DB）
4. 失敗件**不要**只混在「審文案」列表卻看不出差別——選失敗籤時獨立列表；
   三站列表是否仍含失敗件：建議**三站列表排除已標失敗的**，避免重複；
   若排除成本高，至少失敗籤可篩到全部失敗件，三站收合列要有失敗視覺（既有可保留）
5. 計數唯一來源：countPipelineStations / countStations（Fable 已指定）
6. 更新 STATION_OPTIONS 文案；JUMP_STRIP_GROUP_LABELS 同步 §2.2（待輸入→見 T10 收斂）

動檔建議：stationFilter.ts、StageFilterPills.tsx、DraftResultsPanel.tsx、

【T10】填表中「待輸入」勿嚇使用者；快速預覽語意收斂

1. 快速預覽的「未完成／可清理」分組：

   B. 該組改名「未完成草稿」小字＋「可丟棄」，且僅在非本機正在編的其他筆／恢復條情境出現
3. 各站 chip 仍可顯示已生成的 ①②③ 件數（這不是問題）
4. 與 B13 恢復條不衝突：恢復條可留；快速預覽負責「還有哪些稿」總覽
