> 2026-07-08 定案，接續《交接指南》的圖床架構。實作 Phase D 前必讀。
> 原則：快的事給 Vercel、慢的事給 Make（未來換 n8n 只換這一層）、通知以「批次」為單位。

## 一、Showmore 的圖放哪裡（決策樹）

Showmore 匯入 CSV 有四個圖片欄（主要圖片*／廣告圖／商品圖片／商品樣式圖片），
範例檔用的是他們自家 `cdn.showmore.cc` 網址。外部網址是否可用**未經證實**，所以：

```text
第一次匯出時做一個測試：
  拿 1 件商品，CSV 圖片欄填 Shopify CDN 網址（cdn.shopify.com）→ 匯入 Showmore

├─ 成功（Showmore 會自己抓外部圖）
│    → 方案 A：CSV 直接填 Shopify CDN 網址，零額外工作
│      （圖本來就在 Shopify Files，Matrixify 和 Showmore 共用同一批網址）
│
└─ 失敗（只吃自家 CDN）
     → 方案 B：匯出「CSV＋圖片壓縮包」
       · 壓縮包裡的 WebP 以 SKU 命名（CHO-XXX-001-main1.webp），人工上傳好對照
       · CSV 圖片欄留空，去 Showmore 後台上傳圖後在後台補掛
       · 打包在「瀏覽器端」用 JSZip 抓 Shopify CDN 圖組 zip，不經 Vercel
```

兩案圖的**源頭都是 Shopify Files**，不需要為 Showmore 另建圖庫。

**Showmore 加價（2026-07-08 定案）**：Shopify 是未來主力，Showmore 匯出時售價/定價自動加成——
team_settings 加 `showmore_price_markup`（預設 +5%，Admin 可調），加成後再套一次尾數美化
（跳到上一階美化價，如 299→329）。與改寫版文案一樣存 showmore 專用欄位，一件商品只算一次。
副作用是好的：平台價差自然引導客人往 Shopify 消費。

## 二、通知設計（批次為單位，Email 只有 4 種）

**核心修正**：圖片「一張生成好寄一封」太吵，改為**以批次為單位**。

資料面：使用者按「批次送圖／批次發布」時建立 `batch_id`（存 `image_batches`／沿用發布紀錄表），
批內每件商品完成時檢查「同批是否全部到達終態（done 或 failed）」，是 → 觸發一封通知。

| # | 何時寄 | 內容 | 連結到 |
|---|---|---|---|
| 1 | 圖片批次全部完成 | 「你送出的 8 件圖片生成完成（2 件為重生類建議優先看）；失敗 1 件」 | 圖片審核頁 |
| 2 | 發布批次完成 | 「成功 18 件（清單）／失敗 2 件（原因）」 | 發布紀錄頁 |
| 3 | 每週一選品掃描完成 | 「本週 3 家商家共 5 件新品通過過濾」 | 選品情報頁 |
| 4 | 月預算達 80% | 「本月 AI 花費 NT$480／600」 | 儀表板 |

防呆：
- 批次卡住（超過 24 小時未到終態）→ 由每日 Cron 掃出，寄「批次卡住」提醒＋標記可重跑
- 單件失敗**不單獨寄信**，統一收進批次信，避免轟炸
- Email 服務用 Resend（免費 3,000 封/月，遠超需求）

## 三、Make 節點設計（未來換 n8n 只搬這層）

### Scenario 1｜圖片處理（webhook 觸發，非輪詢）

```text
[Webhook 收單] ← Vercel API 在使用者按「送圖」時呼叫，帶 batch_id＋商品清單＋image_flags
   ↓ 逐商品
[Router 依標記分流]
   ├ keep_as_is 全部 → 呼叫 Vercel /api/images/sharp-batch（一件商品的裁切/轉檔一次做完，秒級）
   ├ 去字/重生 每張 → HTTP 呼叫 Image API（Make 等 20–60 秒沒問題）
   │                  → 呼叫 Vercel /api/images/finalize（sharp 統一尺寸→上傳 Shopify Files→寫 DB）
   └ 詳情賣點圖   → 同上（用已存的 image_description，不重跑 Vision）
   ↓
[更新 image_status=awaiting_review]
   ↓
[檢查同批完成度] → 全到終態 → [呼叫 Vercel /api/notify/batch-done → Resend 寄信 #1]
```

### Scenario 2｜批次發布（webhook 觸發）

```text
[Webhook] ← 使用者按「匯入 Shopify」（前台先跑欄位健檢＋預覽）
   ↓ 逐件（間隔 ≥600ms，避開 Shopify 每秒 2 請求限速）
[呼叫 Vercel /api/drafts/{id}/publish]（單件 <10 秒：建商品＋掛 Files 已有的圖）
   ↓ 收集成功/失敗
[寫發布紀錄 batch]＋[清 Supabase 暫存原圖]＋[寄信 #2]
```

### Vercel Cron（免費方案 2 支，每日一次）

1. 抓當日匯率（僅顯示，套用由使用者按）
2. 掃卡住批次＋補寄漏掉的通知（Make webhook 萬一漏接的保險絲）＋清理孤兒暫存圖

### Make 免費額度試算與換手門檻

免費 1,000 操作/月。估每件商品約 8–10 操作（webhook、分流、2–3 次 AI 呼叫、回寫、通知檢查），
**每月上架 80–100 件就會頂到免費上限**。到那時依序換手：

1. 短期：Codex 排程接手同樣流程（0 操作費，但電腦要開著）
2. 正式：Hostinger VPS 自架 n8n（約 NT$150/月、操作無上限），把兩個 Scenario 原樣搬過去——
   節點邏輯照本文件，只是平台換掉，Vercel API 端點完全不用改（這就是 Workflow Provider 可換的意義）

## 四、口袋清單「一鍵存入」具體做法

三階段，由簡到好：

1. **Phase F 初版（零開發捷徑）**：手機複製連結 → 開工具口袋頁貼上。已可用。
2. **iPhone：捷徑 App**（半小時能做好）：建一個「存入潮巢口袋」捷徑，接收分享的網址 →
   POST 到 `/api/pocket`（帶個人 token）。之後在淘寶/蝦皮 App 按分享 → 選捷徑 → 兩秒存入。
3. **Android：PWA Share Target**：工具的 manifest 加 `share_target`，把工具加到主畫面後，
   任何 App 的分享選單會出現「潮巢上架」→ 自動開啟並存入口袋。
   （iOS 的 PWA 不支援 share_target，所以 iPhone 走捷徑方案）

存入時的縮圖/標題：先存純網址即可；伺服器端抓 og:title/og:image 當低成本補強（蝦皮可行，
淘寶常擋，擋掉就顯示純網址，不影響使用）。每人只看自己的口袋（RLS：created_by）。

## 四之一b、商品影片流程（2026-07-08 定案，兩階段）

**第一階段（沿用使用者現行習慣，Phase D 一起做）**：
1. 表單加選填「影片連結」欄（存 `video_urls` JSONB，計畫 10-3 已預留）——
   使用者照舊手動上傳 YouTube 後貼連結
2. 發布時自動：Shopify 用 `productCreateMedia` 的 **EXTERNAL_VIDEO** 把 YouTube 掛進商品媒體輪播
   （不佔空間、商品頁可播）；Showmore 匯出時把連結寫進內文模板
3. 效益：商品頁影片（轉換）＋YouTube 搜尋流量（第二搜尋引擎）＋操作跟現行一樣

**第二階段（後期）**：Worker 經 YouTube Data API 自動上傳影片（需 Google OAuth 授權，較繁瑣故延後）；
或改走 Shopify 原生影片上傳（stagedUpload，同圖床機制），依當時量與習慣擇一。

## 四之二、選品功能開關與推薦回饋（2026-07-08 補）

- team_settings 加 `scouting_enabled`（**預設 false**）：關閉時選品頁只顯示口袋清單（純手動、隨時可用），
  每週掃描排程不啟動；Admin 在設定「自動化」區切換
- 成本參考：Puppeteer 免費；Vision 讀截圖約 20 商家 × 3 頁 × 每週 ≈ **每月 NT$10–20**
- 推薦越來越準的機制（純規則，零訓練）：
  1. 「帶入上架」＝正分、「忽略」＝負分 → 累積偏好（價格帶/IP/類型採用率）→ 候選按「推薦度 ★」排序
  2. 每月一次 LLM 讀採用/忽略紀錄 → **提議**新過濾規則 → Admin 確認才生效
  3. 商家採用率過低（如 <10%）→ 提示停追蹤
  資料面：候選表記 `action: adopted|ignored` 與時間即可，之後全是查詢統計

## 五、「什麼跑在哪」總表（給接手模型的一頁速查）

| 工作 | 跑在哪 | 為什麼 |
|---|---|---|
| 文案生成（Vision＋LLM 串流） | Vercel（同步、串流回應、拆兩支 API） | 人在等，要快；串流避逾時 |
| sharp 裁切/轉 WebP | Vercel（單件一次呼叫） | 秒級完成，免費額度內 |
| AI 生圖/去字（20–60 秒） | Make／未來 n8n | 長等待不能佔 Vercel |
| 上傳 Shopify Files | Vercel API 發起、檔案直傳儲存桶 | 不經 Vercel 本體 |
| 批次發布（限速逐件） | Make 排隊 → 逐件打 Vercel publish API | 避開函式逾時＋Shopify 限速 |
| Email 通知 | Vercel /api/notify → Resend | 批次為單位，共 4 種 |
| 匯率、卡批掃描 | Vercel Cron（每日） | 免費 2 支剛好 |
| 選品掃描（Puppeteer） | Hostinger VPS（與 n8n 同機） | Make/Vercel 都跑不了瀏覽器 |
| 口袋清單存入 | iPhone 捷徑／Android PWA 分享 → /api/pocket | 兩秒完成隨手收藏 |
