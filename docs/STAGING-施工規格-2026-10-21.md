## 3. 程式施工（Sonnet）

> 規則：先讀 `AGENTS.md`；不准新增 `!important`；沒寫到的 UI 不准新增；規格和程式對不上就停下回報 檔案:行號。

### 3.1 新檔 `src/lib/env/nestoryEnv.ts`（純函式，不 import supabase／next）
```ts
export const PROD_SUPABASE_REF = "tbgtqwvuohmdxnxisrgr";
export const PROD_SHOP_DOMAIN = "e0jg81-qe.myshopify.com";
export type NestoryEnv = "production" | "staging" | "local";
export type EnvProblem =
  | "invalid_nestory_env"
  | "prod_env_non_prod_db" | "prod_env_non_prod_shop"
  | "non_prod_env_prod_db" | "non_prod_env_prod_shop";
export function supabaseRefFromUrl(url: string | undefined): string | null;   // https://<ref>.supabase.co[/...] → <ref>；其他 → null
export function normalizeShopDomain(d: string | undefined): string | null;    // 去 https://、去尾斜線、小寫；空 → null
export function readNestoryEnvironment(env?: Record<string, string | undefined>): {
  declared: NestoryEnv | null; effective: NestoryEnv;
  supabaseRef: string | null; supabaseIsProd: boolean;
  shopDomain: string | null; shopIsProd: boolean;
  problems: EnvProblem[];
};
export function environmentBannerModel(r: ReturnType<typeof readNestoryEnvironment>):
  { tone: "staging" | "danger"; text: string } | null;
export class ShopifyEnvironmentMismatchError extends Error { problems: EnvProblem[] }
export function assertShopifyEnvironment(env?: Record<string, string | undefined>): void; // problems 非空 → throw 上面的 Error
```
預設 `env = process.env`。讀 `NESTORY_ENV`、`NEXT_PUBLIC_SUPABASE_URL`、`SHOPIFY_STORE_DOMAIN`。規則逐條照做：
1. `declared`：`NESTORY_ENV` 是三個值之一就用它；有設但不是這三個值 → `declared=null`，加入 `invalid_nestory_env`。
2. `effective`：`declared ?? (supabaseIsProd && shopIsProd ? "production" : "local")`。這樣在老闆還沒設 `NESTORY_ENV` 之前，現在的正式站和預覽部署行為完全不變。
3. `effective==="production"`：`!supabaseIsProd` → `prod_env_non_prod_db`；`!shopIsProd` → `prod_env_non_prod_shop`。
4. `effective!=="production"`：`supabaseIsProd` → `non_prod_env_prod_db`；`shopIsProd` → `non_prod_env_prod_shop`。
5. 橫幅（`environmentBannerModel`）：
   - problems 非空 → `{tone:"danger", text:"⛔ 環境設定錯誤：" + 問題文字用「、」串接 + "。已停止寫入 Shopify，請找 Claude。"}`。問題文字：`invalid_nestory_env`＝NESTORY_ENV 的值不正確；`prod_env_non_prod_db`＝正式站連到的不是正式資料庫；`prod_env_non_prod_shop`＝正式站連到的不是正式商店；`non_prod_env_prod_db`＝測試／本機環境連到了正式資料庫；`non_prod_env_prod_shop`＝測試／本機環境連到了正式商店。
   - 否則 `staging` → `{tone:"staging", text:"🧪 測試場：資料庫和 Shopify 都是測試用的，可以放心按。"}`；`local` → `{tone:"staging", text:"💻 本機開發環境"}`；`production` → `null`。

### 3.6 測試：新檔 `scripts/verify-staging-fence.mjs`，接進 `verify:all`
至少要測：
1. `readNestoryEnvironment` 矩陣（≥12 例）：declared 為 production／staging／local／未設／亂填，乘上資料庫是正式／非正式、商店是正式／非正式／空，比對 `effective` 和 `problems`。要包含「未設＋兩者都正式→production、無問題」和「未設＋都不是正式→local、無問題」。
2. `supabaseRefFromUrl` 和 `normalizeShopDomain` 的邊界：尾斜線、大寫、`https://` 前綴、空值、非 supabase 網址。
3. `environmentBannerModel` 每種情況的 tone 和文字逐字比對。
4. `adminToken`：設定不一致時 throw `ShopifyEnvironmentMismatchError`，**而且 fetch 完全沒被呼叫**；設定一致時 fetch 有被呼叫。
5. `fence.mjs`：正式 ref → throw；三個來源 ref 不一致 → throw；pooler 和 direct 兩種網址都要能解析。
6. seed 的唯讀 Proxy：對來源呼叫 insert、update、upsert、delete、rpc、storage.upload 都會 throw。
7. 靜態檢查：`layout.tsx` 裡 `<EnvironmentBanner />` 出現在 `<header className="topbar">` 之前；`globals.css` 這段新 CSS 沒有 `!important`、沒有十六進位色碼。
