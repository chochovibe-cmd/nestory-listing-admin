## 〇、工具定位（一句話）

**潮巢團隊的商品上架工作流平台**：貼標題＋丟圖片 → AI 產文案與圖片 → 人工審核 →
一鍵發布 Shopify（CSV 匯出 Matrixify / Showmore 為備援）→ 未來擴充儀表板與選品情報。

## 一、根本問題診斷（為什麼現在用起來很怪）

### 現在的實際流程（`WorkspaceInputPanel.tsx` 的 stage 機制）

```text
填標題/價格/語氣 → 按「建立商品並生成文案」
    ↓
草稿建立 →【文案立刻開始生成 ← 此時圖片根本還沒上傳！】
    ↓
表單整個消失，換成「上傳圖片」畫面 ← 使用者覺得莫名其妙的地方
    ↓
圖片傳完 → 去右邊卡片看結果
```

兩個後果：
1. **UX 彆扭**：圖片上傳被排在「事後」，像是補交作業，而且表單會整個不見
2. **AI 永遠看不到圖片**：文案生成時圖片不存在，`image_description` 沒人寫入，
   Vision 想接也接不上——流程順序讓它不可能發生

### 正確的流程（本計畫的核心修正，Mockup 已照此設計）

```text
一個畫面一次填完：標題＋價格＋圖片（先選檔、本地預覽）＋款式＋語氣
    ↓ 按「生成」
1. 上傳圖片（Supabase Storage，可平行）
2. Vision 辨識（主圖+詳情圖 → image_description；規格圖 → spec_text OCR 簡轉繁）
3. LLM 文案生成（這次真的有圖片資訊了）
4. 定價計算 → 寫回草稿 → 右欄卡片顯示
    ↓
表單清空，可立刻填下一筆（批次連續作業）；結果在右欄卡片流累積
```

生成中的進度（上傳→辨識→文案→定價）直接顯示在右欄的「生成中卡片」裡，
取代原 mockup 清單的獨立流程軌道（B-1）——同一個資訊，更省空間。

## 三、Phase 計畫

### Phase A｜後端補洞（不動版面，最先做）

1. **Shopify 真實發布**：關掉 `SHOPIFY_PUBLISH_MOCK`，接真 Admin API token（Vercel 環境變數），
   第一階段只建 DRAFT 商品＋回填 product ID／後台連結
2. **Vision 接入**：新增 `/api/analyze-images`（或併入 generate 流程）——
   主圖＋詳情圖用便宜 Vision 模型（GPT-4o-mini 等級）產 `image_description`；
   規格圖 OCR＋簡轉繁寫入 `spec_text`；`/api/generate` 把兩者傳給 CopyProvider（specText 目前沒接線）
3. 技術修正：max_tokens 1500 → 3000+（「詳細」文風會截斷）；
   更新預設模型（Claude 端改新版 Sonnet、模型名稱維持 env 可覆蓋）
4. 查重 API：`/api/drafts/dedupe?title=...`，用標題相似度＋IP/角色比對，回傳可能重複的既有商品

### Phase B｜前台流程重整（解決「很怪」的主因）

1. **單一畫面流**：圖片選擇移進表單（先選檔、本地縮圖預覽、可單張移除），
   按「生成」才依序上傳→辨識→生成；表單不再消失
2. 生成中卡片內建四步進度條（取代獨立 rail）
3. 圖片區徽章改誠實文案：「1:1 裁切（生成時處理）」→ 在裁切功能上線前先寫「生成時上傳」
4. 待處理清單（B-4）：表單底部顯示本次 session 已送出的商品 chips，點擊捲動到對應卡片
5. 上傳失敗確認橫幅（B-5）：有圖失敗時，發布／匯出按鈕先跳二次確認
6. 草稿自動保存：表單欄位 debounce 寫 localStorage，重整不丟失
7. 查重提示卡：標題輸入後呼叫 dedupe API，發現相似商品時顯示黃色提示（同一件／不是，繼續）

### Phase C｜App Shell 導覽改版

1. 桌面側邊欄＋手機四格 tabbar（照 Mockup）
2. 設定整併成獨立頁/彈窗：AI Provider、定價規則（現有 collapsible 搬入）、
   自動化模式（排程／Make／n8n／關閉）、LINE 通知開關、Shopify 連線狀態
3. 佇列頁補三段狀態 chips＋建立者名字（團隊感）

### Phase D｜圖片 Pipeline 第二段＋圖片審核頁

流程（背景執行，人不用等）：

```text
文案核准後 → worker 領取圖片工作
  ├ 依卡片上的人工標記分流：保留（僅 sharp 轉檔壓縮/裁切）／去字（inpainting）／
  │  整張重生（image generate）／正方形化（outpainting）
  ├ 規格圖去簡體字
  └ 詳情賣點圖生成（一定執行）
→ image_status = 待審核 → 出現在「圖片審核」頁 → 確認使用／拒絕＋修改指令重生
→ 全部確認 → 圖片上傳 Shopify media → 可發布
```

技術定位（已定案，不再討論）：
- 圖片裁切／縮圖：**sharp 跑在 Vercel**（這是當初選 Vercel 而非 Cloudflare 的核心原因）
- AI 生圖／去字：Image Provider 架構（GPT Image 起步，Flux/Ideogram/Recraft 可換），
  由 Workflow（先 Make 免費版，之後 n8n 自架）協調，**不交給扣哥**（生圖太慢會卡住 session）
- 扣哥只負責：領工作、寫回 Shopify、狀態管理
- 完成後通知：LINE 或 Telegram（擇一，Phase D 尾聲）

### Phase E｜儀表板

- 資料來源：Supabase（上架量、成本、各成員產出）、Shopify Admin API（銷量、營收）、
  Google Search Console API（曝光、點擊、熱門查詢字）
- 呈現：本週上架數／平均每商品成本／GSC 曝光與點擊／熱門 IP 排行（銷量×搜尋量）
- 目的：給選品方向依據——哪些 IP 有流量沒商品、哪些商品有曝光沒點擊（標題該修）
- 前置：GSC 需先完成網站資源驗證；等有真實上架數據再動工才有意義

### Phase F｜選品情報（商家追蹤法）

已定案策略（不教 AI 判斷「值不值得賣」）：

1. 人工篩選 10–20 個定位相近的淘寶商家（一次性）
2. 排程掃描：Puppeteer 開商家頁截圖 → GPT-4o-mini Vision 讀商品標題/價格
   （跑 Hostinger VPS，跟 n8n 同機，無額外主機費；不需要 Computer Use）
3. 規則過濾（無 AI）：未收錄？價格在販售區間？圖片夠？
4. 候選商品進「選品情報」頁＋推播通知 → 你看一眼 → 「帶入新增商品」一鍵預填表單

### 貫穿各 Phase 的原則（給實作模型）

- UI／Workflow／AI／Shopify 四層分離；Provider、Workflow 平台不寫死（env / 設定切換）
- 狀態獨立：`generation_status` / `image_status` / `publish_status` / `review_status`，可 Retry 可 Resume
- Tags/Collections 永遠由規則引擎產出，不給 LLM 自由發揮
- SQL 一律只產 `.sql` 檔給使用者貼 SQL Editor，不跑 CLI
- 敏感 key 只放伺服器端環境變數
- 每完成一階段回報：完成什麼／改了哪些檔案／下一步建議／需要手動操作嗎（Y/N）

## 七、v7.2 修訂（2026-07-07 使用者實測回饋後定案，以此為準）

### 資訊架構重整（解決「佇列頁 vs 生成區」混淆）

| 頁面 | 定位 |
|---|---|
| 新增商品 | 左表單＋右工作流卡片。卡片流＝「我的・未發布」，上方階段篩選：全部／文案待審／圖片處理中／圖片待審／待發布／失敗 |
| 圖片審核 | 預設只看自己的（一條龍：誰上架誰審到底），可切全部 |
| 發布紀錄（取代原佇列頁） | 每次批次匯出/匯入一張卡：類型（Shopify API／Showmore CSV／Matrixify CSV）、成功/失敗筆數、時間、操作人，點開看明細、失敗可單獨重跑 |
| 商品庫 | **不做獨立頁**，改為上方 Bar 按鈕開彈窗：搜尋、補圖、修文案、看上架人/時間 |
| 儀表板（初版） | 今日/本週上架數、與上週比較、成員上架數、本月 AI 花費 vs 月預算（達 80% 提醒）、每件平均成本＋模型明細、IP 佔比。GSC/訂單數據後期接 |
| 選品情報 | 商家追蹤改**每週掃描**＋新增「口袋清單」：隨手貼連結存起來，有空一鍵帶入上架，上架後自動移除 |

### 表單區定案

1. 銷售狀態回到標題旁小 pill（多數商品是海外代購不常改）；庫存全狀態可改、預設無上限，切「現貨」時展開提醒
2. 網址抓取＋截圖辨識**升為常態功能**（Puppeteer 免費＋Vision 每次約 NT$0.15–0.3），手動填標題降為備用；
   不限淘寶（蝦皮/官網也收）；截圖辨識可多張，自動填：標題／人民幣成本／特色小標→補充備註／規格彈窗截圖→規格表
3. **IP/角色/類型偵測卡從表單移除**：改為生成時由 AI 判斷（Vision＋標題＋備註），結果顯示在卡片收合列的 mini chips；
   角色不在資料庫時卡片內顯示 ⚠＋「一鍵新增角色」
4. 表單查重只做網址比對；IP＋角色＋類型三維度查重在生成後顯示為卡片警告
5. 規格圖 OCR 取消「餵文案」用途（文案參考規格直接讀規格欄位）；規格圖標記只剩圖片處理用途（第二段去簡體字）
6. 商品圖片：主圖縮圖放大、其餘較小；手機**長按**拖曳排序（防誤觸）＋動畫回饋
7. Variant：圖片欄移到最前；「依角色建立」改為**角色多選勾選面板**（該款有出哪些角色自己勾，同角色多造型可重複）；
   快速維度按鈕（＋尺寸／＋顏色／＋自訂）；成本欄跟上方同幣別（¥ 填 ¥），下行小字顯示換算後 NT$ 售價/定價；手動列 ✎ 保護
8. 定價：成本（CNY×匯率 或 TWD）→ 常駐顯示 成本/售價/定價(劃線)/利潤；「直填台幣售價定價」＝原手動覆蓋功能；
   新增「顯示定價」開關（不是每件都做特價）
9. AI 文案設定補回：長度（精簡/標準/詳細）＋Web Search 開關；語氣擴為 6 款（黑膠文藝/日系溫柔/可愛輕鬆/中二熱血/小編口吻/依 IP 自動匹配）
10. **標題清洗規則（加進 System Prompt）**：自動剔除平台活動詞（618、免運、節慶禮物套語等短期情境），依商品本身重寫長銷使用情境
11. 補充備註明確標示「供文案與詳情賣點圖參考」，截圖辨識自動填入

### 卡片區定案

- 收合狀態即可讀：主圖縮圖＋標題＋IP/角色/類型 chips＋售價(定價劃線)＋利潤＋⚠待確認數＋三段狀態，一眼掃出哪張要點開
- 展開後**卡片內分頁**：文案／定價／圖片／Tags／SEO（參考分支任務原設計），避免 20 張卡全展開拉很長
- 「本次已送出」條＝快速跳轉 chips，卡片本體在卡片流，不重複
- 匯出列：匯入 Shopify（先預覽商品頁）／Matrixify（先預覽 CSV）／Showmore（CSV＋WebP 圖包）

### 匯出圖床邏輯（回答 Showmore 問題）

- Matrixify：圖片只需**公開 URL**（Supabase Storage 或 Shopify CDN 皆可），不必先進 Shopify
- Shopify API 匯入：圖片直接走 stagedUpload 進 Shopify 媒體庫
- Showmore：匯入 CSV 用的是他們自家 CDN 網址，外部 URL 不保證支援 → 匯出「CSV＋已轉好尺寸的 WebP 圖片壓縮包」，到 Showmore 後台上傳圖後貼上

### 其他定案

- 名稱統一用「Codex」（不寫扣哥）；Worker 順位：Make 免費版（預設）→ 額度不足退 Codex → 穩定後自架 n8n
- 通知：先做 Email（預設開），LINE Bot 保留選項後期接
- 上方 Bar 精簡：匯率（每日自動更新）＋「LLM 已連線/測試模式」切換＋商品庫＋設定；模型選擇移入設定頁
- 設定頁新增 **System Prompt 前台編輯器**：Admin 限定，每次儲存記錄版本號/時間/修改人，可還原歷史版本

## 八、v7.3 修訂（2026-07-07 第二輪實測＋外部審查採納，最終版）

### 已拍板的四個決策
1. **利潤可手改（A 方案）**：手填利潤 → 售價自動跳到「不低於 成本＋利潤 的最近美化價」，旁顯示美化後實際利潤
2. **表單模型快速切換只影響單次**：預設 Provider 在設定由 Admin 定；表單按鈕顯示「本次：GPT（預設 Claude）」，生成後自動回預設
3. **側欄改頂部導覽分頁**：頁面層＝色塊 tab，卡片內容層＝底線 tab，兩個導覽層級視覺分開
4. **定價二選一**：「🏷 特價模式（售價＋定價劃線，預設）」／「單一售價（不填 compare_at_price）」——對應 Shopify/Showmore 的劃線特價規則

### 全站視覺規則（實作時寫進 globals.css 的約定）
- **使用者選取＝外框強調（2px accent 邊框＋淡底），系統狀態＝淡色實心 chip**，兩種語意不共用樣式
- 狀態色詞彙表統一：灰=未開始／黃=進行中／綠=完成／紅=失敗，狀態圓點用同一個元件
- 狀態一律全文字（「文案已生成・待審核」「圖片未標記」「尚未發布」），不用單獨 emoji/縮寫
- 按鈕分兩級：影響結果的操作（核准/送圖/確認使用）用大尺寸，輔助操作用 mini
- 正式實作時關鍵 icon 換 SVG（lucide），emoji 只留裝飾（tone card 等）
- 主題預設淺色（nordic），localStorage 記住每裝置上次選擇；暗色主題提高對比
