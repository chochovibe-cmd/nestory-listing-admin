## 1. 背景（已查證）

- **假款式**：淘寶匯入會把「購買須知」「資訊說明｜勿拍」「售罄勿拍」「聯繫客服定製賀卡」這類非商品選項當成款式，一路帶上 Shopify。PUBLISH-GUARD（#45）已經會在發布時**擋下**這些款式（regex 在發布前檢查的模組裡），但匯入時沒有排除。
- **款式名稱**：目前匯入和發布都不轉換。只有完整生成時會跑 OpenCC 簡轉繁（字級）加一份手寫詞表，詞表缺「內存卡→記憶卡」這類詞。沒有符號清理。每個款式還重複整段商品名，例如「Pingu螢幕耳機【升級版】+Pingu絨毛吊飾（馬桶款）」。
  - 可以下手的位置：`mapVariantRows`、generate pass、`variantSummary`。
- **SKU**：
  - 現在 Shopify 上的 SKU 是淘寶的 skuId（13 位數字），單款商品常常是空的。
  - SKU 原本來自 AI 輸出，但 prompt 自相矛盾（`chaochaoPrompt.ts` 約 :203 和 :222）。
  - `generateSku` 只在 Shopify 單款 fallback 時用到。
- **款式圖**：`product_variants.image_id` 有記錄每款對應的圖，但 `toBulkVariantInput` 從來不送 `mediaId`，所以 Shopify 上所有款式都沒有綁圖。
- **售價 0 元**：`buildVariantPublishPlan` 裡 `price: row.twd_price ?? 0`，沒售價的款式會用 0 元上架。
- **價格**：#49 改了尾數規則（1680 以下不變；1680 以上每 100 元有 x80、x99 兩個點）。但已經存在的草稿和已上架商品**沒有回填**，例如相機 31701317、Pingu e4ba2299 在 Shopify 上仍是舊價。
  - 目前要重算價格，只能在結果卡改一下成本再存；沒有一鍵重算。
  - `syncShopifyProduct` 的完整同步會把 Shopify 後台手動設的「售完／追蹤庫存」改回不追蹤，所以**不能拿它來做價格重同步**。

## 2. 範圍

### A. 匯入時排除假款式
- **共用** PUBLISH-GUARD 的假款式判斷（同一個函式／regex，不要另寫一份）。
- 匯入（`mapVariantRows` 和擷取匯入流程）時，符合的選項不建立成款式。
- 把排除結果寫進草稿 warnings：「已排除 N 個非商品款式：…」。
- 規格頁籤顯示「已排除的款式」摺疊清單，每一筆可以「恢復」。
- 「套組／≥2 個／盒／入」**不排除**。它們是真的商品，照舊由 PUBLISH-GUARD 要求確認成本。

### B. 款式名稱整理（老闆已決定：規則整理＋AI 潤飾成台灣用語，看過前後對照再套用）
- **規則層**（固定規則，可測試）：
  - 去頭尾空白、多個空白合一。
  - 全形／半形統一，括號統一成全形「（）」，【】保留。
  - 清掉裝飾性行銷詞（正版授權、包郵、現貨、新品、熱賣…）。但如果拿掉後款式名稱會重複或變空，就保留。
  - **保留商品名，不縮短**（老闆 10-14 決定）：每款裡重複的商品名照樣留著，例如「Pingu螢幕耳機【升級版】」維持原樣，只整理符號、用語。**不要**做「拿掉共同前綴」。
  - OpenCC 簡轉繁，加上**集中一份**台灣詞表（至少要有：內存卡→記憶卡、U盤→隨身碟、充電寶→行動電源、數據線→傳輸線、屏幕→螢幕、軟件→軟體、視頻→影片）。
  - 維度名稱也一起整理（例：颜色分类→款式、尺码→尺寸）。
- **AI 潤飾層**：
  - 每筆草稿只呼叫一次，把全部款式名稱一起送進去，請它改成自然的台灣用語。
  - 程式要驗證 AI 的結果，任何一條不符就退回規則層的結果：
    1. 數字、單位、英文、角色名都要保留；
    2. 款式名稱仍然互不重複；
    3. 長度不超過規則結果 +4 個字，也不少於規則結果 −4 個字（不准靠刪掉商品名變短）；
    4. 不能新增原文沒有的資訊；
    5. 規則結果裡的商品名／品牌／IP 名稱必須仍然出現。
- **UI**：
  - 規格頁籤加「整理款式名稱」按鈕。
  - 點了開一個對照表：原名／整理後，每列可以勾選或取消，也可以手動改，最後按「套用」。
  - **不可以沒經過預覽就自動套用**。
  - 原始名稱要保留下來（例如存成 `source_option*_value`，或放進既有的 meta 欄位；需要加欄位就寫 migration 檔）。
  - 匯入時可以先自動跑規則層（不跑 AI），但原名一定要留著。

### C. SKU
- **格式**：`NS-<草稿 UUID 前 6 碼大寫>-<兩位序號>`，例如 `NS-E4BA22-01`。單款商品就是 `-01`。（老闆 10-14 已確認）
- SKU 改成由程式決定，不再從 AI 輸出拿。把 prompt 裡和 SKU 有關的矛盾指示拿掉。
- 序號照款式的 `sort_order`。使用者手動改過的 SKU 一律不覆蓋（需要的話加 `sku_locked`，或用既有的鎖定欄位）。
- 淘寶 skuId 改存在內部欄位（例如 `source_sku_id`）給採購用，不再送到 Shopify 的 SKU。

### D. 款式綁圖
- 發布時，把每個款式的 `image_id` 對應到 Shopify 商品上的 MediaImage id。新建款式時帶 `mediaId`；續傳或更新時，用 Shopify 的 `productVariantsBulkUpdate`（或 `productVariantAppendMedia`）補綁。
- 如果款式的圖還不是這個商品的 media，就先加進商品 media，再綁定。
- 圖要等 Shopify 處理完（status READY）才能綁，要有等待或重試的機制，但必須在單筆 60 秒內收尾。
- 綁不上只記 warning，不能讓發布失敗。
- 以上用的 Shopify API 名稱與欄位，請對照 repo 實際使用的 Admin API 版本確認。
- 續傳路徑（`planResumeVariantSync`）也要綁圖。

### E. 售價防呆
- 款式的 `twd_price` 為空或 ≤0 時：加進 PUBLISH-GUARD 的 blocker，訊息「款式「X」沒有售價」，擋下發布。
- `buildVariantPublishPlan` 拿掉 `?? 0`。

### F. 依公式重算售價＋已上架商品的「價格／款式圖重同步」
1. **規格頁籤「依公式重算售價」按鈕**：
   - 用目前的尾數規則重算所有**沒鎖定**的款式。
   - 先顯示「舊價 → 新價」對照，勾選後套用。
   - 鎖定的款式不動。
2. **已上架商品的重同步工具**（放在發布紀錄或工具頁）：
   - 列出 active_published 的草稿中「重算後的價格和目前價格不同」或「款式圖還沒綁」的商品。
   - 每筆顯示每個款式的「舊價 → 新價」，以及要綁的圖。
   - 老闆勾選後執行，**一筆一個請求**（照 PUBLISH-BATCH 的 stepwise 做法，不要一個請求跑整批）。
   - 只同步 **款式售價／原價（compare-at）／款式綁圖**。不改標題、描述、圖片順序、庫存、庫存政策、商品狀態、管道。
   - 不可以呼叫完整的 `syncShopifyProduct`。
   - 同步成功後，本地的 `twd_price` 和 Shopify 一致，並且記錄一筆紀錄。
   - **預設全部不勾選**，因為這會改到線上售價（多數是降價）；但上方要有「全選」鈕，所以「全選 → 同步勾選的商品」兩下就能一次做完。（Claude 建議，老闆可改）
   - 版面示意：
     ```
     價格／款式圖重同步　　　　　　　　[全選] [同步勾選的商品（0）]
     ☐ 相機 31701317　　 款式 A：5480 → 4980　款式 B：5480 → 5280　｜要綁圖 2 張
     ☐ Pingu e4ba2299　 款式 標準版：2280 → 1980 ……　　　　　　　｜要綁圖 3 張
     ```
   - 執行時逐筆顯示「同步中／完成／失敗（原因）」，失敗的可以單筆重試。

## 3. 測試與驗收

- 新增 `scripts/verify-variant-clean.mjs`，加進 `package.json` 和 `verify:all`，至少涵蓋：
  - 假款式在匯入時被排除、套組沒被排除；
  - 規則層：括號、空白、詞表、行銷詞（拿掉後重複或變空就保留）、**商品名保留不被刪**；
  - AI 驗證器：數字、角色名或商品名被拿掉時退回規則結果；
  - SKU 格式、序號、手動改過的不覆蓋；
  - 綁圖 payload 有帶 mediaId、續傳也會綁、綁不上只記 warning；
  - 價格 null 被擋下；
  - 重同步只送價格和 media 欄位（用假的 Shopify 斷言 mutation 內容）、一筆一個請求。
- 必須全部通過：`npx tsc --noEmit`、`npm run verify:all`（含 verify:publish-guard、publish-batch、variant-pricing、prepare-images）、`npm run build`。
- **Preview 實測清單**（給老闆）：
  1. 匯入一筆有「購買須知」款式的淘寶商品 → 規格頁看不到它，「已排除的款式」清單裡有，可以恢復。
