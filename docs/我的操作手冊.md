# 我的操作手冊（使用者小抄，各情境直接複製貼上）

> 2026-07-08 整理。AGENTS.md 是給模型的規則，這份是給你自己的。
> 心法一句話：**凡是不想被照抄的要寫成禁令；凡是想被記住的要存在檔案裡，不是對話裡。**

---

## 情境 1｜開新對話（每次開工都貼這段）

```text
請依序讀這兩份，其他文件等做到相關項目再讀：
1. docs/交接指南-給接手的AI模型.md
2. docs/施工清單.md（唯一進度真相）
讀完後告訴我：目前進度到哪、你這個 session 打算做清單上的哪 3–5 項、需要我準備什麼。
等我確認才動手。做完把清單打勾＋在進度筆記加一行。
SQL 只產檔不跑 CLI；不要 push 除非我說可以。
```

搭配三個鐵習慣：
- **一個對話只做 3–5 項，做完就開新對話**（長對話後段模型會忘東忘西）
- **收工必問**：「對照施工清單，念出你這次完成了哪幾項、哪些沒做完」
- 模型提出跟計畫矛盾的建議 →「先引用文件的哪一節，再說你想改什麼」

## 情境 2｜要加新功能／改版面

```text
做施工清單 BX 項（或描述新功能）：
1. 行為：使用者按了會發生什麼（一兩句）
2. 樣式：功能和位置照 Mockup，風格以現網站為準；沿用 OO 頁面的 OO 元件樣式
3. 照 AGENTS.md 三段式先給我文字版設計方案（新增什麼／保留什麼／衝突點問我），
   我確認後再實作，做完截 淺色＋暗色＋手機 三張圖給我比對
```

要點：**一次只改一件事**（加功能＋順便美化混在一起必爛）；永遠指定「長得像誰」的參照物。

## 情境 3｜要換風格／調視覺

- **小調**（換色/陰影/圓角/字級）→ 一句話直接說：「主色換成 OO、陰影再淡一點」，不用先方案
- **大改** → 用試衣間：

```text
我想試一個新風格（附截圖或網站連結：要像這樣的感覺）。
不要動現有主題，做成一個新的主題選項讓我在真網站上切換比較，
我滿意再轉正、不滿意刪掉。
```

要點：**給截圖不給形容詞**——「高級一點」每個模型解讀都不同，一張圖勝過一百個形容詞。
平常看到喜歡的網站就截圖存起來。

## 情境 4｜嫌畫面擠／說明太多

```text
這一區留白加大、說明文字收進 ? 圖示、縮圖放大——照 AGENTS.md 的資訊密度規範做。
```

（記得：Mockup 的灰色小字是規格註記不是 UI 文案，模型如果搬進正式版，指著這條糾正它）

## 情境 5｜驗收（做完不能只聽它說「完成了」）

- 前台變更 → 要三張截圖：淺色＋暗色＋手機
- Phase A＋B 完成 → **一件真商品跑完整條龍**（輸入→生成→發布 Shopify 草稿→去後台親眼看）
- 密度驗收 → 找一位沒看過工具的同事，不講解，3 分鐘內能完成一件上架才過關
- 改 System Prompt → 跑「10 件黃金測試集」對照新舊版輸出

## 情境 6｜模型選擇與費用（用 CC 接手時的分配）

| 時機 | 模型 | 原因 |
|---|---|---|
| 每個 Phase 的**第一個 session**（讀文件、拆解該 Phase 的執行計畫） | Opus | 規劃需要判斷力，開好頭之後都省 |
| 照清單執行的日常 session（大多數時間） | **Sonnet** | 規格已寫死，執行綽綽有餘 |
| 三個高難度熱點：A2/A4 串流實作、D2 Make 串接、A14 真品實測除錯 | Opus | 整合除錯最燒腦 |
| 同一個問題 Sonnet 修兩次還沒好 | 換 Opus | 別讓 Sonnet 猜第三次，token 反而燒更多 |
| 文件小修、文案微調 | Sonnet（有 Haiku 可選就 Haiku） | 便宜快 |

- Make 免費版每月約撐 80–100 件商品，儀表板額度錶接近上限＝該換手（Codex 頂替→自架 n8n）

## 情境 7｜你要親自準備的東西（模型做不了的）

- [ ] Shopify Admin API token（建立時勾 **write_products＋write_files** 兩個權限）→ 交給模型設進 Vercel
- [ ] 挑出你自己寫過**最滿意的 2–3 篇商品文案** → 當品牌語氣黃金範例餵進 System Prompt（反模板化的靈魂）
- [ ] 準備「10 件黃金測試集」商品（熱門/冷門 IP、多角色、二手、規格複雜各 2 件）
- [ ] 平常存喜歡的網站/版面截圖（未來改風格用）
- [ ] 口袋清單養成習慣：看到想上架的商品先丟連結

## 安全紅線（永遠不變）

- 任何 API key/token 只交給模型設進 Vercel 環境變數，**不貼在對話裡讓它寫進程式碼**
- SQL 一律自己去 Supabase SQL Editor 貼，模型只產檔
- 模型說要 push/deploy → 先問「會影響線上正在用的版本嗎」再同意
- 刪除類操作（刪表、刪檔、清資料）→ 要求它先說明會刪掉什麼、能不能復原
