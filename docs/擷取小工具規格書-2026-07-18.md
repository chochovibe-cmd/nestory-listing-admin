> `docs/流程重構規格書-2026-07-16.md` §15 追加定案（桌機 Chrome 擴充為主、
> 手機「分享網址→收藏草稿→回桌機補抓」半套）＋回饋 48（真爬蟲提前）＋回饋 60（順手抓影片 URL）。
> 狀態：**規格待老闆確認**；確認後由 Fable 出工人開場指令分包施工。

## 1. 目標與非目標

**目標**：老闆在自己的 Chrome 開著淘寶（或蝦皮/官網）商品頁時，按一下擷取鈕，
頁面上的標題／價格／SKU 規格表／圖片／影片 URL／參數表整包送進上架工具，
自動落成「待輸入」草稿並填表，省掉全部手動複製貼上。

**非目標**（明確不做，防機能蔓延）：
- 不自動化瀏覽（不開背景瀏覽器、不維護登入 cookie、不批量掃頁——那是 F 階段 B/C 路線）
- 不繞過任何登入／驗證（人本來就在頁上，擷取的是眼前 DOM）
- 不在本包做選品判斷（爬蟲選品＝Phase F/G 另案）

## 2. 架構總覽

```
[Chrome 擴充 MV3]──讀當前分頁 DOM──┐
                                    ├─ POST /api/import/product-page（token 認證）
[手機半套：分享/貼網址]────────────┘         │
                                              ▼
                                   建 product_drafts（status=待輸入）
                                   ＋ raw_capture JSON 完整留底
                                   ＋ 圖片 URL 由伺服器代抓入 Storage（走既有管線）
                                   ＋ 去重檢查（沿用 A12 查重）
                                              ▼
                                   前台開啟該草稿＝表單已預填（還原草稿既有機制）
```

## 3. 擷取欄位（誠實原則：抓不到留空，不猜）

| 欄位 | 來源 | 落點 |
|---|---|---|
| 原始標題 | 頁面 title/DOM | taobao_title |
| 售價／劃線原價 | 價格區 DOM | 成本欄（CNY）＋原價備註 |
| SKU 規格表（顏色×尺寸等多維） | SKU 選擇區 DOM | **raw_capture.sku_table（JSON 原樣留底）**；款式列先以現行單維模型塞入，多維交叉展開等包二（回饋 10）落地後再自動升級——本包不解決多維模型 |
| 主圖 URL 列表 | 相簿區 | 伺服器代抓入 Storage → product_images(main) |
| 詳情圖 URL 列表 | 詳情區 img | 同上 → product_images(detail) |
| 商品影片 URL | 影片元素 src | draft 影片欄（回饋 60 軌 1 的入口） |
| 參數表（品牌/材質/尺寸…） | 參數區 | 規格備註欄；品牌字樣餵 product_brand 偵測鏈（75a） |
| 來源網址 | location.href | source_url（查重鍵） |

`raw_capture` 全量 JSON 存草稿欄位或附表：**擷取當下抓到什麼就留什麼**，
之後模型升級（多維規格、影片管線）可以回放舊擷取免重抓。

## 4. 接收端 API

- `POST /api/import/product-page`
- 認證：**個人擷取 token**（設定頁產生/重設，擴充儲存；不用帳密、不用 cookie 跨域）。
  token 走 header，伺服器對 profiles 綁定；錯誤/過期回明確訊息
- 防重：同 source_url 近期已有草稿 → 回「已存在，開啟該草稿？」不重複落稿（A12 查重沿用）
- 圖片代抓：伺服器單次 fetch 圖片 URL 入 Storage（帶 referer 對策；抓失敗列 warning 不擋落稿）
- 回應：draft id＋預填欄位清單＋warnings（給擴充顯示結果）
- 鐵則：route.ts 只 export HTTP method（AGENTS 新規，P0-63 教訓）

## 5. 擷取端（Chrome 擴充 MV3）

- 形式：MV3 擴充（流程規格書 §15 定案「擴充為主」；書籤款只在擴充受阻時做備援）
- 互動：工具列按鈕一鍵擷取 → 完成/失敗徽章＋一行結果（「已建草稿：標題×圖 8×款式 4」）
- 站點適配器：淘寶（含天貓）優先；蝦皮/一般官網用通用 meta/DOM 後備規則
- 選擇器集中一檔好維護（淘寶改版只改 selectors）；抓不到的欄位誠實回報「未抓到」
- 不注入第三方腳本、不常駐監聽——按了才動

## 6. 手機半套（後段，依 §15 定案）

分享/複製商品網址 → 貼進上架工具「收藏網址」入口 → 建佔位草稿（只有 URL＋標題輕抓）
→ 回桌機開淘寶頁按擷取補全。PWA share target 可選，先做貼上版。

## 7. UI 邊界（與 UIUX 分工）

本工程的前台面＝**零新版面**：落稿走既有草稿機制、結果回饋走 UX-A toast、
設定頁加一列「擷取 token」（沿用現有設定列樣式）。任何新畫面需求（例如擷取
歷史清單）等 UX 線定版後另議——規格書先不含。

## 8. 分包與順序

| 包 | 內容 | 驗收 |
|---|---|---|
| CAP-1 | 接收 API＋token＋落稿＋圖片代抓＋去重＋verify 腳本 | 用 curl/腳本餵樣本 JSON → 草稿出現且表單預填、重複 URL 擋下 |
| CAP-2 | Chrome 擴充（淘寶適配器＋通用後備） | 老闆真實淘寶頁按一下 → 草稿齊全；抓不到的欄位誠實列出 |
| CAP-3 | 手機貼網址半套＋（可選）share target | 手機貼 URL → 佔位草稿 → 桌機補抓成功 |

CAP-1 純後端可立即發工（不撞 UX 線）；CAP-2 完成後老闆實測一輪再進 CAP-3。

## 9. 風險與對策

- 淘寶改版 → 選擇器集中管理＋raw_capture 留底＋通用後備規則
- 圖片防盜鏈 → 伺服器代抓帶 referer；仍失敗則留 URL＋warning，人工補圖
- token 外洩 → 設定頁一鍵重設；token 只能建草稿，無讀取/刪除權限
- 多維 SKU 塞單維模型會失真 → 原樣 JSON 留底＋款式列標 warning「多維已壓平，
  展開待包二」，不假裝正確

## 10. 待老闆確認的裁決點

1. **CAP-1 立即發工？**（建議：是，純後端與 UX 不撞）
2. token 放設定頁 OK？（建議：是，比環境變數親民）
3. 蝦皮/官網通用後備要不要進 CAP-2？（建議：進，成本低；淘寶仍是主力適配）
4. 手機半套的優先度（建議：CAP-3 殿後，等你實際用過桌機版再決定要不要）
