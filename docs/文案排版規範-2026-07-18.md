# 文案排版規範（2026-07-18；COPY C1.1 Owner corrective 更新 2026-08-25）

> 本檔＝文案排版與 Shopify description semantic hierarchy 的現行唯一真相。
> 原始來源資料可保留簡體；Nestory 生成後供審核／Shopify 顧客看到的 AI 文字一律台灣繁中。

## 1. 一般 tone（原有 6 tone，格式完全維持）

儲存格式仍是純文字，段落間空一行：

```text
（開頭段，無標題）

◈ 商品亮點
・重點詞：具體說明

◈ 適合誰
・具體對象／使用情境

◈ 商品資訊
・只寫有 evidence 的資訊

◈ 購買提醒
・依材質／類型客製
```

Shopify／Nestory Preview 的一般 tone formatter 維持既有 contract：

- `◈ 標題` → `<h3><strong>◈ 標題</strong></h3>`
- 一般段落 → `<p>`
- `・`／`➼` → `<ul><li>`
- 歷史 A/B/C/D/E 格式繼續相容

COPY C1.1 **不得把原 6 tone 全部改成 h2**。

## 2. 潮巢導購版（COPY C1.1 Boss Shopify layout）

`潮巢導購版` 不再使用 C1 初版的 `◈ 收藏亮點／◈ 為什麼會想帶回家／◈ 商品資訊／◈ 購買提醒`。

模型輸出的純文字 source contract：

```text
商品介紹
（生活感破題＋資訊完整的商品介紹正文，2–4 個短段落）

收藏亮點
・短重點詞：具體事實＋使用／選擇意義
・短重點詞：具體事實＋使用／選擇意義
・短重點詞：具體事實＋使用／選擇意義

導購小標：依商品動態生成的自然小標
（導購正文 1–2 個短段落）
```

Shopify 最終主商品介紹 HTML 必須 deterministic render 成：

```html
<h2>商品介紹</h2>
<p>到貨狀態提醒</p>
<p>商品介紹正文...</p>
<h2>收藏亮點</h2>
<ul>
  <li>...</li>
  <li>...</li>
  <li>...</li>
</ul>
<h2>依商品動態生成的導購小標</h2>
<p>導購正文...</p>
```

鐵則：

- 主商品介紹恰好是三個語意 H2：`商品介紹`、`收藏亮點`、動態導購小標。
- 不輸出 `◈`，主 section 不 render 成 `<h3>`。
- 主商品介紹不再追加 `商品資訊`、`購買提醒` H2／section；規格走 `spec_text`／Shopify specs metafield，FAQ 走既有 FAQ flow。
- 不在 Shopify HTML 塞 inline font-size／標題尺寸／行距；視覺由現有 Shopify Theme 接手。
- Nestory description Preview 使用同一套 `h2 / p / ul / li` semantic hierarchy，不因此改全站 CSS。
- 只借舊老闆工具的 HTML semantic hierarchy；**不保存、不模仿、不照抄競品／舊工具文案句子，也不把它們當 few-shot**。

## 3. 潮巢導購版到貨提醒

只在 C1.1 Boss formatter 中，放在 `<h2>商品介紹</h2>` 後：

| 銷售狀態 | 文案 |
|---|---|
| 海外代購（約14天） | 此為海外代購商品，預估約 14 天。 |
| 預購中 | 此為預購商品，到貨時程以頁面說明為準。 |
| 台灣現貨 | 此為台灣現貨商品，約 1–3 個工作天出貨。 |
| 二手現貨 | 此為二手現貨商品，品況請見商品資訊，約 1–3 個工作天出貨。 |

原 6 tone 的既有 20 句 tone-specific 提醒不改。

## 4. 潮巢導購版人味／anti-AI voice

語氣目標：真的在賣 IP 周邊的潮巢小編，而不是 AI 商品文。

- 有人味、有溫度、幽默、可愛、有生活感。
- 可以吐槽、角色梗；戰鬥系 IP 適合時可以少量中二（裝備／覺醒／戰力／召喚等語感），但不能把語氣梗寫成不存在的商品功能。
- 優先抓角色個性、商品真正用途、使用情境、消費者的小慾望與實際購買理由。
- 商品介紹仍要吃進有 evidence 的品牌／IP／角色／類型／系列／造型／材質／尺寸／容量／配件／功能／款式／使用方式。
- evidence 足夠時，商品介紹＋收藏亮點至少使用 3 個商品獨有具體資訊；不足就少寫，不硬湊。
- feature → benefit 必須合理，精確數字沒有 evidence 就不寫。

禁止或強烈避免：

`總是覺得……嗎？`、`是否正在尋找……`、`一大力作`、`滿載童趣`、`最佳選擇`、`完美選擇`、`絕對不能錯過`、`完美地將……`、`帶給你無限……`、`陪伴左右`、`為生活增添一抹……`、`不僅……更……`、`療癒指數爆表`、`收藏價值滿滿`、`送禮自用兩相宜`、`值得入手`、`值得考慮`。

## 5. 標題 C1.1 corrective（不是完整 formula redesign）

第一段目前仍維持既有 **品牌 × IP**，本包不決定未來是否改成 IP × 品牌。

正式三段骨架：

```text
品牌 × IP | 角色・角色 商品類型 | 特色
```

- 第二段＝角色 + detected product type；多角色用 `・`；無角色只留 product type；只有 product type 缺失才只剩角色。
- `A|B|C`、`A｜B｜C`、`A | B | C` 最終一律 normalize 為 `A | B | C`。
- 後端 deterministic normalization 必須補第二段 product type，不只靠 prompt。
- 60/80 字 clamp contract 與第三段 blacklist 繼續有效。
- 第三段若只因 product type 移到第二段而出現純重複，可安全去掉重複詞；不趁機 redesign 其他標題公式。

## 6. Customer-facing 台灣繁中 + 正式規格

Full generation persist 前，以下 AI customer-facing fields 必須 deterministic Taiwan Traditional localize：

- title_zh / enriched title
- description
- FAQ
- SEO title
- meta description
- why_we_chose_it
- product_highlights
- spec_text

`taobao_title`、`original_title`、raw OCR/source cache 是 evidence，不改原文。

Full generation 的 spec canonical 規則：

1. provider `spec` 有內容 → 使用 AI 根據 evidence 整理的乾淨 spec。
2. provider `spec` 空 → 才 fallback 既有 `spec_text`。
3. 選中的 spec → 台灣繁中 → strip customer source markers → 移除平台／賣家後台垃圾欄位 → persist。
4. single-field description／FAQ／SEO regen **不改 spec_text**；普通 rerender/save 也不應重寫 spec。

顧客規格優先保留：品牌、IP、系列、角色、商品類型、材質、尺寸、容量、包裝、內容物／配件、款式、功能、盲盒規則、授權資訊；電子商品依 evidence 可保留電源／充電／連線／燈效等。

不原封不動保留：分類、貨品分類、顏色分類、適用人群、是否為特殊用途化妝品、流行趨勢詞、場景類型、適用節日、賣家促銷欄、平台活動欄等低價值後台欄位。

如果這些後台欄位內藏真正購買規則（例：`盲盒不可指定`、`隨機1個`），只留下有用事實並改寫成顧客語言，例如：`盲盒方式：隨機出貨，不可指定款式`。

尺寸、容量、重量、張數、個數、記憶體等精確數字仍只可取自 evidence，不可目測猜測或自行補值。

## 7. Parser / compatibility

`sectionHeaders.ts` 仍是舊格式的 single source of truth：

- `商品亮點`／`收藏亮點` → B
- `適合誰`／`為什麼會想帶回家` → C
- `商品資訊` → D
- `購買提醒` → E

C1.1 Boss layout 由專屬 boundary formatter 解析 `商品介紹／收藏亮點／導購小標`，不建立第二套舊 A–E parser，也不改一般 6 tone contract。
