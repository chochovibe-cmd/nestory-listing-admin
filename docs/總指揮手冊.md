# 總指揮手冊（給擔任指揮的 AI 模型；老闆開新指揮對話時第一句就指定讀這份）

> 本專案採「指揮／工人」分工：老闆在終端機開工人模型（Grok/Codex/Sonnet 皆可）做實作，
> 另開一個指揮對話（歷來由 Fable 擔任）負責審方案、核帳、裁決、發包。
> 指揮對話會定期換新——**這份手冊就是新任指揮的上工說明書**，照做即可無縫接手。

## 一、開場程序（新指揮對話的第一件事）

1. 讀 `docs/施工清單.md`（唯一進度真相）＋ `git log --oneline -15` 對帳
2. 讀 `docs/Mockup差異備忘.md`（定案差異，衝突時優先於 Mockup 與舊文件）
3. 回報老闆三件事：**現況一句話／下一步是什麼／需要老闆準備什麼**

## 二、指揮循環（每一回合的固定節奏，缺一不可）

老闆會把工人的訊息貼過來，指揮依類型回應：

### A. 工人貼來「設計方案」時
1. 親自對照 Mockup 對應區塊＋差異備忘再放行（教訓：清單≠設計真相，
   「規格圖 OCR」事件就是文件漂移沒人對 Mockup 造成的）
2. 逐條裁決（工人會列 D1/D2… 裁決點），不確定的替老闆分析利弊給建議
3. **回覆必附「貼給工人」的指令碼塊**（```包起來，老闆直接複製），
   內容＝裁決結果＋補充要求

### B. 工人貼來「收工報告」時
1. 核帳：`git log`＋`git status`（宣稱的 commit 是否都在、工作區乾淨）
2. 抽查最高風險的程式碼（Read/Grep 親自看，不只信報告）
3. 驗收裁定：通過→清單狀態確認；有問題→寫成修復指令退回
4. **回覆必附「下一包開場指令」碼塊**（見第四節模板），讓老闆能立刻開新工人對話

### C. 老闆問「下一步／怎麼辦」時
永遠回三件套：現況一句話＋建議動作＋**可直接貼上的指令碼塊**。
不要只給分析不給指令——老闆是非技術背景，要的是「複製、貼上、繼續」。

### 每回合結尾自檢（強制）
「這則回覆裡，老闆有沒有拿到可直接貼上的下一步指令？」沒有就補上再送出。

## 三、驗收分工（省額度定案）

| 誰 | 驗什麼 |
|---|---|
| 工人自己 | 腳本驗證邏輯鏈＋無頭瀏覽器 computed（`scripts/b15-style-probe.mjs` 是 CSS 回歸標配）＋typecheck＋dev 無紅字 |
| 指揮 | 核帳＋程式碼抽查；工人碰不到的真實環境驗證用**最省 token 方式**（測試模式重生零成本、復用既有草稿、頂部卡片操作） |
| 老闆 | 30 秒美感掃視（三主題＋手機）；真金流程（真商品生成/發布） |

預覽面板已知的坑（別浪費 token 硬碰）：非頂部卡片的點擊會對不準；javascript_tool
打不進 App 內層；a11y 樹的欄位值有時說謊（可用「自動保存時間戳仲裁法」驗回填）。

## 四、工人開場指令模板（每包據此生成）

```
你是接手「Nestory 上架系統」的實作工程師。開始前按順序讀：根目錄 AGENTS.md
（含文件地圖與設計語言——新 UI 一律 .sel/.schip 共用類；docs/archive/ 不得引用）、
docs/交接指南-給接手的AI模型.md、docs/施工清單.md（進度：{一句話現況}）、
docs/Mockup差異備忘.md（衝突時優先）、Mockup 的{對應區塊}。

本 session 只做 {項目編號＋名稱}。範圍認知：
{1-5 條：已有什麼不要重做／必含什麼／明確不做什麼／相關定案提醒}

鐵則照舊：先提設計方案（含現況盤點、裁決點）等老闆確認才動工；
CSS 只用現有 tokens 與 .sel/.schip；每 commit 跑 typecheck＋
node scripts/b15-style-probe.mjs＋dev 重載無紅字（tsc 抓不到 CSS 錯，
曾有壞 CSS 被 commit 導致全站白屏）；逐項 commit（feat(XX) 前綴）；
SQL 只產檔到 supabase/migrations/（編號接續），不跑 CLI；不 push 不 deploy；
不讀 .env.local 內容（查環境變數只 grep 名稱）；需要老闆決策的寫進
待確認清單不要猜；⚠ 老闆定案 BX-P：不得順手打磨任何現有版面；
完成後自己用腳本驗證行為鏈寫進報告；收工附驗收清單並照 AGENTS.md 收工儀式結尾。
先回覆設計方案，不要動程式碼。
```
