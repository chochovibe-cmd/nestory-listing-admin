## 一、文案生成呼叫架構（定案）

```text
按「生成」
① 前端離線：contentGenerator 規則引擎 → Tags／Collections／標題骨架（0 元，立即顯示）
② POST /api/analyze-images（同步，獨立一支避 Vercel 10 秒限制）
   ├ 主圖＋詳情圖 → Vision 平行呼叫（Promise.all）→ image_description 存 DB
   └ 標記為規格圖的 → OCR 簡轉繁 → spec_text 存 DB
③ POST /api/generate（串流回應，設 maxDuration）
   輸入：標題＋備註＋規格欄＋image_description＋spec_text＋已建檔 IP 清單＋語氣＋長度
   輸出：逐欄串流顯示 → 解析 → 規則引擎用 detected IP/角色/類型跑正式 Tags → 寫 DB＋generation_history
④ 定價寫入（前端已即時計算）
單欄位重生：同一支 API 帶 field 參數，把其他欄位現值當上下文送入，只重寫該欄（省錢、保持一致）
失敗處理：解析失敗自動重試「一次」（附格式提醒），再失敗就標 failed 給人工重試——不做無限 retry 迴圈
```

### 兩個實作必踩的坑（Codex 注意）

1. **串流 × JSON 矛盾**：Prompt 若要求純 JSON，串流時使用者會看到大括號亂碼。
   → 輸出格式改「分段標記」：`<偵測>…</偵測><標題>…</標題><描述>…` 逐段顯示，收完再整體解析。
   JSON 只作為最後的解析目標格式或乾脆棄用。
2. **開 Prompt Caching**：System Prompt（~2000 tokens）＋IP 清單每次重送很浪費。
   Anthropic `cache_control` 把 system＋IP 清單標為快取 → 連續上架時輸入成本降約九成。

## 三之三、反模板化設計（核心需求：每篇都是針對該商品的高導購力文案）

老闆工具模板化的根因＝規則填空。LLM 一次生成好很多，但仍會收斂慣用句，六層防線：

1. **素材差異化（治本）**：Prompt 鐵律「描述必須引用至少 3 個本商品獨有的視覺細節
   （來自 image_description），禁止使用可套在任何商品上的形容」——細節別的商品抄不走
2. **開場角度輪替**：系統維護角度清單（情境帶入／角色性格梗／材質觸感／收藏視角／小幽默／畫面感…），
   每次生成由**程式隨機指定一個**塞進 prompt——變化由系統保證，不靠 AI 自覺
3. **禁複製記憶**：prompt 附「最近 5 件同類商品的開頭句」，明令避開相似句式（幾十 token）
4. **品牌語氣靠範例**：把使用者自己寫過最滿意的 2–3 篇實際文案放進 System Prompt 當黃金範例
   （搭配 Prompt Caching 成本不變）——形容詞會被各自解讀，真實範例才會被模仿。
   **請使用者挑三篇得意之作，這是他要親自做的事**
5. **導購力結構**（附 before/after 範例進 prompt）：開場擊中「想要的理由」非商品描述；
   亮點寫「得到什麼」非「有什麼」（短絨布料 → 捏下去會回彈的療癒感）；
   適合誰寫具體人物場景；收尾一句行動暗示
6. **重生＝換角度**：「↺重新生成」自動指定不同開場角度，版本間有真實差異，挑選才有意義

**驗收標準**：黃金測試集盲測——AI 文案混入使用者自寫文案中，分不出（或 AI 更好）才算過關。

## 三之四、競品比價（按鈕觸發，不自動跑）

- 入口：結果卡片「定價」分頁的「🔍 查競品價」按鈕；每次約 NT$0.3–1，僅使用者點擊才查
- 查詢：用偵測後的「IP＋角色＋類型」組關鍵字（不用原始標題）→ 搜尋 API（Tavily 免費額度起步）
  抓蝦皮/露天/PChome → 便宜模型整理價格區間，**排除最低 20% 疑似非正版**
- 呈現：行情區間＋「你高/低於中位數 X%」提示＋一鍵「降到最近美化價」／「維持」＋來源連結
  （人眼判斷是否同等級商品）；**絕不自動改價**
- 結果快取進 draft（查過的不重查），優先序：Phase E 之後的選配

## 三之五、雙平台（Shopify＋Showmore）SEO 差異化

背景：兩平台會上同批商品，語意級重複內容會被 Google 擇一收錄。**段落排列組合不夠**（判重看語意）。

1. **改寫層（必做）**：匯出 Showmore 時用便宜模型真改寫（同義改寫＋換開場角度＋FAQ 換題），
   結果存 `showmore_title / showmore_description / showmore_faq` 欄位——**每件只改寫一次**，
   重複匯出不再花錢。成本約 NT$0.1–0.3/件
2. **關鍵字分工層（零成本）**：兩平台標題用不同關鍵字系——Shopify 用中文正名
   （吉伊卡哇 小八 絨毛吊飾），Showmore 用 ip_catalog 的 aliases 別名系（Chiikawa 小八娃娃 掛件），
   規則引擎換字即可。兩邊各吃一組搜尋詞，總曝光變大
3. 圖片、價格相同無妨，判重主要在文字

### Showmore 文案模板 v2（2026-07-08 依使用者實際範例定案，匯出時套用）

**標題公式**（與 Shopify 標題刻意不同，兼作 SEO 差異化）：
`【{IP}】{品牌×}{商品主體}-{特色詞}｜{類別詞}｜收藏送禮推薦`

**簡述欄**：一句話（「{IP}人氣角色周邊，適合收藏、日常使用與送禮。」可由改寫模型客製）

**內文結構**（A–E 字母退役，改純文字符號，Showmore 內文欄確定相容）：
```
商品介紹        ← A 段改寫版 1–2 句
商品特色        ← ✔ 短句 ×3 橫排
商品資訊        ← ➼ 列點：商品名稱/聯名品牌/角色/材質/版型規格/備註/用途
常見問題 FAQ    ← Q1 導購型＋Q2 現貨公版＋Q3 色差公版（原 E 段併入）
【交貨方式說明】【運送方式說明】 ← 公版尾段
```

**鐵則**：
1. 商品資訊只列**有公開依據**的項目，沒有的整行略過，不硬湊
2. 絕不出現來源平台（淘寶/閑魚等為內部資訊）
3. 絕不在文案內寫價格（避免改價要改文案）
4. ➼ 備註行可帶一句該 IP 的梗式幽默（品牌口吻位，如「請勿試圖用拉鍊穿越牆壁」）
5. 公版尾段（交貨＋運送）存 team_settings 可編輯，匯出時自動附加——改一處全部生效；
   Shopify 站內已有公版設定，不附加

### 描述嵌圖（發布/匯出時自動）

## 三之七、官網文章工坊（上線後功能，Blog 引流）

- 流程：AI 讀商品庫數據＋節慶日曆 → 每月提案 4–8 題（標題/角度/目標關鍵字/關聯商品）→
  使用者挑 → 生成草稿（沿用品牌語氣黃金範例）→ 人工修 → Shopify Blog API 發布
- 內容支柱輪替：IP 文化觀點／角色入門指南（高搜尋量）／節慶送禮清單（長尾收割）／
  選物幕後／新品開箱
- 文章 SEO 規格（依使用者範本體檢定案）：**前 70% 品牌敘事＋後 30% 自然帶商品**；
  必有 H2/H3 小標、內部連結（商品/專區）、結尾溫柔 CTA、目標關鍵字自然織入、每 2–3 段配情境圖
- 品牌聲音基準（兩篇黃金範例，各代表一種文型，都要收進文章 prompt）：
  ① 「從宅文化到生活風格」——純品牌敘事型（短句節奏、去汙名化、真誠不推銷）
  ② 「HUNTER×HUNTER 獵人又回來了」——SEO 結構型（問句小標分段、角色關鍵字自然密植、
     按粉絲類型導購分流「角色派/篇章派」、結尾自然 CTA 到選物頁）——這篇已示範 70/30 公式的正解
- 共同特徵＝「去 AI 味」的定義：具體記憶點（不空泛）、承認粉絲的真實處境、
  短段落、不用驚嘆號堆砌、導購藏在「幫你分類自己」的段落裡而非叫賣

## 三之六、儀表板 AI 顧問卡（Phase E 後段，按鈕版起步）

- 觸發：儀表板「產生本週建議」按鈕（約 NT$0.3–1/次）；穩定後可改每月自動一次（Make 排程）
- 輸入：**統計摘要**（非原始資料）——IP 佔比、上架量/成本、重生率、選品採用/忽略、
  未來加 GSC/訂單＋「上次建議與採納情況」
- 輸出要求（寫進該 prompt）：3–5 條建議，每條必附數據依據，禁止「多上熱門 IP」式空話
- 每次建議存 advice_log（時間/內容/是否採納），形成回饋迴圈
- 誠實限制：GSC/訂單接上前，建議僅基於商品庫結構與成本，深度有限——所以排程版不急

## 五、儀表板優先序（初版做 1–3，其餘後補）

1. **今日待辦卡**（最實用）：文案待審 N・圖片待審 N・失敗 N・待發布 N，各自可點跳轉——開工第一眼
2. **流程漏斗（本週）**：輸入→文案審過→圖審過→已發布 各階段件數＋平均停留時間 → 一眼看出瓶頸關卡
3. **Make 額度錶**：本月操作數/1,000，達 80% 提醒（連動《自動化流程設計》的換手門檻）
4. 重生率：文案重生次數/件、圖片拒絕率——偏高＝Prompt 或生圖品質該調（連動成本）
5. Tag 健康度：警告 tag 數＋待整理提議數（admin 的維護提醒）
6. 上架日曆熱圖（GitHub 綠格子風）——上架動力可視化
7. 後期（接 GSC/訂單後）：曝光高零點擊商品（標題該改）、搜尋熱但商品少的 IP 缺口（連選品）

資料模型前提（已在交接指南）：每筆 AI 花費記到 draft_id；漏斗需要各狀態的時間戳
（status 變更時記 updated timestamps 或寫 automation_logs）。
