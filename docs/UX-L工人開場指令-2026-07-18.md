【T61】ResultCard 殘留 window.confirm → 站內二次確認
────────
現況（掃過 src）：全站 window.confirm 只剩 ResultCard 三處——皆「捨棄未存編輯」類，
不是上架 ACTIVE（上架已是 double-confirm）：

1. **全部拿掉 window.confirm**（這三處）。
2. 改成與 UX-E 一致的 **inline 二次確認**（第一次 arm 文案「再點一次確認…」，第二次才執行；

4. 取消／逾時：點其他處或數秒後解除 arm（若現有 pattern 有就跟；沒有可簡化為再點同一鈕）。
5. 手機可點、文案白話。

【T62】ResultCard 瞬時回饋改 toast（清 setMessage 噪音）
────────
痛點 Claude 1-5／UX-I 明確延後：ResultCard 大量 setMessage，成功失敗易被忽略或與 toast 混用。

指揮定案（對齊通知三層 T2）：
1. **瞬時成功／失敗** → `showToast(..., "success"|"error"|"warn")`  
   例：儲存失敗、重生失敗／完成、核准失敗、退回失敗、連線失敗、讀版本歷史失敗、一鍵新增角色結果。
2. **進行中**（儲存中…／重生中…／核准中…）：
   - 優先：按鈕 disabled＋短文案 或 toast 可省略「中…」只 toast 結果  
   - 若需原地進度，可留 **一行** 輕量 status，但成功／失敗結果仍要 toast，且結束後清掉「中…」
3. **阻斷必修**（⛔ 擋核准的 warning 摘要）：可留卡內 notice（不要只靠 toast 一閃沒）。
4. **double-confirm arm 文案**（「再點一次確認…」）：可留卡內，**不要**改成 toast（toast 不做確認）。
5. 已 toast 的路徑不要再 setMessage 同一句（避免雙重）。
6. **不做**：重寫整張卡邏輯、改 API、掃全站其他檔的 setMessage（本包焦點 ResultCard）。

動檔：ResultCard.tsx。
驗：存檔失敗有 toast；成功有 toast；卡上不再堆一長串歷史 message（arm／阻斷除外）。
