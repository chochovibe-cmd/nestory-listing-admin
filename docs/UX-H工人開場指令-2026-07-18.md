【T40】按鈕 class 收斂
────────
痛點 C1-8：同一「主要行動」角色散成十幾個 class（btn-add、btn-gen*、ir-btn-confirm…），
padding／字重／圓角略不同，以後調主按鈕要改十幾處。

指揮定案：
1. **設計系統目標**（以 globals 為單一真相）：
   - 主要行動：`.button.primary`（已有則強化為預設主 CTA 樣式）
   - 次要／線框：`.button`（無 primary）
   - 危險：`.button.danger`（若尚無，用現有 danger token 補一組，**禁止自創色值**）
   - 成功（少用）：`.button.success` 僅在已有語意處（如確認通過）需要時再加
   - 小鈕：沿用既有 `.btn-mini`／`.mini-btn` **二選一收斂**（優先保留使用面較廣者，另一 alias 指向同規則），
     不要再發明第三種 mini
2. **收斂策略（只加不減行為）**：
   - 先在 CSS 讓舊 class（btn-gen、ir-btn-confirm…）**組合或繼承** `.button.primary` 的核心視覺
     （可用多 selector 掛同一規則，或 `@extend` 不可用則逗號並寫）
   - 高流量 TSX 逐步改 className 到 `.button.primary`；一次性全站改 class 名風險高，
     **允許本包採「CSS 合流為主＋關鍵路徑 TSX 改名」**，但修法清單必須列「本包會改哪些 TSX」
3. **不做**：重做整站所有按鈕形狀、改流程、換 icon 庫、改 double-confirm 邏輯（UX-E 已過）。
4. 主操作仍遵守：min-height 40px+（手機可點 ≥44px 處維持）。

驗：掃工作檯生成鈕、工廠確認／拒絕、空狀態 CTA、批次主動作——主色按鈕看起來像同一家人；三主題不破。

────────
【T41】StatusBadge 明確 map（禁 includes）
────────
痛點 C1-3：`status.includes("ready")` 讓 `csv_ready` 變綠「ready」、像已上架；
`archived` 無 class 幾乎隱形。

指揮定案：
1. 改 `StatusBadge.tsx` 為 **明確 Record／switch map**（status → { label, tone }），**禁止** includes 鏈。
2. tone 對齊既有 `.status.ready`／`.processing`／`.failed`（或現有 status 色 class）；
   若缺 archived／neutral，用 muted／既有灰階 token 補 **一個** `.status.archived`（或 `.status.neutral`），
   三主題都要可讀。
3. 至少保證：
   | status | 不得誤判成 | 建議 tone |
   |---|---|---|
   | csv_ready | active_published／ready 綠「已上架感」 | neutral 或獨立「備妥」 |
   | archived | 無色隱形 | archived／muted 可見 |
   | active_published／draft_created／completed | — | ready 系 OK |
   | failed／api_failed／needs_revision | — | failed 系 |
   | pending*／processing／publishing | — | processing 系 |
4. `STATUS_LABELS` 可保留／補齊；未知 status 顯示原文 + neutral，不要炸。
5. 不改 DB enum、不改 API。

驗：佇列／結果卡上 csv_ready 與已上架顏色不同；封存有可見樣式；typecheck 綠。

【T42】字級：內容 ≥13–14px；9–10 僅輔助
────────
痛點 C1-4：globals 大量 9–12px，長時間審文案吃力。

指揮定案：
1. **內容性**（必須可讀）：草稿標題、文案預覽本文、表單 input／textarea、主要說明句
   → 至少 **13px**，優先 **14px**（沿用／微調既有 token 或現有 class，禁止魔法亂數散落）。
2. **允許維持 9–10px**：chip 角標、欄位 uppercase 小標（若 T43 仍保留英數小標）、badge 計數、表格欄名。
3. **做法**：
   - 優先改「高頻閱讀面」：ResultCard 文案預覽、表單 label 旁主輸入、佇列標題列
   - 不要一次把全檔 9px 全砍光（會爆版）；修法清單列「本包會拉大的選擇器清單」
4. 不改行高到怪、不改整站 rem root（除非極有把握且寫進清單等放行）。

驗：站① 展開文案預覽、新增表單主欄——中文清楚可讀；手機 375 不橫向爆、卡片不擠成一團。

────────
【T43】中文 label 取消無意義 uppercase
────────
痛點 G/C：`text-transform: uppercase` 套在中文段小標無意義，英數還可能變難讀。

指揮定案：
1. 掃描 globals（及少數 module）裡 `text-transform: uppercase`。
2. **中文為主的 UI 小標**（如「基本資料」「文案風格」「待辦」類）：拿掉 uppercase。
3. **可保留 uppercase** 的情況（寫進清單說明）：
   - 純英文／縮寫且設計意圖就是字距標（少見）
   - 不影響中文的 letter-spacing 可留
4. 不要為了去 uppercase 改掉語意文案本身。

驗：三主題下中文小標不再「假全大寫」；英數工具列仍整齊即可。

────────
【T44】圖片 alt
────────
痛點 C1-6：多處 next/image 與 img 缺 alt；審圖是核心流程。

指揮定案：
1. 盤點 `src/components`（必要時 app）內商品相關 `<img>`／`next/image`：缺 alt 或 alt="" 僅裝飾者要分類。
2. **有意義的商品圖**至少：
   - 有標題時：`{title} 主圖`／`{title} 詳情`／`原圖`／`處理後` 等短句
   - 無標題：`商品圖`／`縮圖` 等不空白
3. **純裝飾**（間隔 icon、無資訊）：`alt=""` + 若可及性需要可 aria-hidden——但商品審核圖**不算**裝飾。
4. 優先：ImageReviewPanel、ImageCompareSlider、ResultCard 縮圖、輸入區縮圖、佇列縮圖。
5. 不改上傳 API、不改 storage。

驗：核帳可用 DOM／掃 code：主路徑商品圖皆有非空 alt（裝飾除外）；無 layout 迴歸。

────────
【T49】軟刪除淡出 + hover 柔陰影（小劑量）
────────
痛點 C2-3：Mockup 有軟刪淡出與柔陰影；現行偏硬。AGENTS：**不要整站 Mockup 化**。

指揮定案：
1. **柔陰影**：僅 hover／非選取卡片或縮圖 hover 可用雙層柔影（可用現有 `--shadow-m` 或輕量多一層，
   **色值跟現有 shadow token 走**，禁止新品牌色）。
2. **選取態硬邊偏移**（`.sel`／`--card-active-shadow` 等）**禁止改掉**——那是現站記憶點。
3. **軟刪／封存淡出**：移除圖片、封存列等「即將從列表消失」時，短 transition opacity（約 0.2–0.35s）
   再移除；若 UX-E 封存 10s undo 已存在，淡出不得破壞復原行為（先淡出 UI、undo 仍可用）。
4. 不做：全站毛玻璃 topbar、大改 radius、新動畫庫。

驗：hover 卡片略柔、選取仍硬邊；刪圖／封存不「閃沒」；三主題 OK。
