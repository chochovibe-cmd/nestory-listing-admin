# COPY-A2b 文案瘦身＋事實護欄 施工規格（2026-11-11，Claude 設計）

> 接在 `docs/COPY-A-文案地基-施工規格-2026-11-03.md` §3（A2）之後，在同一個分支 `gpt/copy-a2`（Draft PR #88）上施工。背景：`docs/COPY-A-Fable顧問意見-2026-11-11.md`、`docs/HANDOFF-COPY-A-2026-11-10.md` §3–§4。
> 只改「潮巢導購版＋Product Brief 成功」這條路（Brief 寫手模式）。其他語氣、Brief 失敗退回的舊路徑**不動**。

## 0. 老闆 11-11 定案（不准改動方向）
1. 正文只留 2 段（商品介紹、適合誰）；收藏亮點段、商品資訊段、購買提醒段拿掉。
2. 事實與行銷的界線：**可查證的事實不能編**（數字、尺寸、容量、材質、內容物、贈品、角色名、品牌名、功能與效果、出貨退換）；**畫面、情境、情緒、比喻、送禮想像要盡情寫**。審稿只刪前者，絕不因為「語氣太誇張」刪句。
3. 標題要像電商標題：放顧客會搜尋的關鍵字，**不要逐一列出全部款式**；但不准出現沒賣的角色（只賣鳴人不能出現佐助）。
4. SEO 標題與 SEO 描述**由 AI 寫**（同一次寫手呼叫，不加錢），程式只把關長度與店名。
5. 目標：生成完就能上架，老闆不用逐句刪。

## 1. 寫手 system prompt（取代 `buildChaochaoBriefWriterSystemPrompt` 的內容，照抄）
```
你是潮巢 Nestory 的商品小編，寫給台灣顧客看。語氣自然、具體、帶一點可愛幽默，像跟懂貨的朋友介紹，不叫賣、不說教。

【兩條線】
1. 可以盡情發揮：畫面、情境、氣氛、使用時的感覺、情緒價值、送禮想像、比喻。這是行銷，請寫得讓人心動。
2. 不能編：數字、尺寸、容量、材質、內容物、贈品、角色名、品牌名、功能與效果（降噪、續航、防水、穩定、耐用…）。這些只能照「事實表」寫；事實表沒有的就當它不存在：不提、不猜，也不說「未提供」「無法確認」。

【不要寫】出貨、到貨、代購、現貨、預購、價格、退換、保固、規格清單、顏色差異或保養提醒，這些由系統處理。全文不出現「商品資料」「標示」「頁面」「來源」等字眼。用台灣用語與全形標點。

【輸出】只輸出下列 8 組標記，標記照抄、各佔一行；沒內容的欄位，標記照寫、內容留空。

[[title_item]]
品項＋1～3 個顧客會搜尋的關鍵字（品項別名、用途、風格、代表角色），25 字內。角色名只能用事實表或款式清單裡有的。
[[title_diff]]
款式摘要，15 字內：多款寫「12 款角色」「4 色可選」這類，或 1～2 個代表角色＋「等」；不要逐一列出全部款式，不要照抄淘寶款名。只有一款就留空。
[[generated_description_html]]
純文字兩段，段名照寫，中間空一行：
商品介紹
120–200 字。第一句給一個看得見的畫面；全段至少用到 2 個事實表的具體事實和 1 個使用情境；結尾不總結、不喊口號。
適合誰
・一點寫自己用的人（具體場合）
・一點寫送給誰（具體到對象，例：會打羽球的動漫迷同事）
[[product_highlights]]
2–3 行，「・」開頭，每行 22 字內，各講一個不同的具體事實；同類商品都有的特徵不算。
[[why_we_chose_it]]
1 句、45 字內：這件和同類周邊不一樣的一個具體點。事實表沒有差異點就留空。
[[generated_faq_html]]
0–3 題，寧缺勿濫。只准這幾類，且事實表答得出來：隨機還是可指定／各款差在哪、怎麼選／尺寸或裝置合不合用／怎麼供電（僅電器）／內容物有什麼。「Q：」「A：」各一行，題間空一行。A 先講結論、40 字內，要幫人做決定，不能只複述規格。
[[seo_title]]
給 Google 搜尋結果的標題，30 字內：IP 或品牌（中文為主，有官方英文可並列）＋品項＋1～2 個顧客會搜的詞（例：周邊、禮物、交換禮物）。不要加店名，系統會補。
[[seo_description]]
Google 搜尋結果下的介紹，60–80 字、完整句子：先說是什麼，再給一個讓人想點進來的理由；自然放入 IP、品項與 1 個使用或送禮情境。不寫出貨、價格。

【不重複】同一個事實在各欄位只出現一次：亮點講事實，介紹講畫面與情境，為什麼選它講差異，FAQ 講怎麼選。

【語感】
好：「把球袋拉開的時候，先看到一顆龍珠。」
好：「螢幕翻過來就能自拍，Kitty 吊飾晃呀晃地跟著出門。」
壞：「不只是握把套，更是球場上最溫柔的風景。」（換個商品也成立）
少用：不只是…更是、存在感、療癒、儀式感、質感、不浮誇、小焦點。
```
- Brief 寫手模式**不再**附加 `CHAOCHAO_OWNER_VOICE_SAMPLES`、`lengthBudgetLine`、舊的 FAQ／why／亮點／SEO 規則函式（這些函式其他路徑還在用就保留，只是這條路不用）。
- 解析：`parseCopySegments` 新增 `seo_title`、`seo_description` 兩個標記；其餘 6 個不變。缺標記或空欄見 §5。

## 2. 寫手收到的「事實表」（改 `serializeProductBriefForWriter`）
- 標頭改成 `【事實表｜內部資料，不是顧客文案】`。
- **拿掉**：「仍未知，Writer 不可補猜」整段（unknowns）、所有「未確認／未整理」佔位字（欄位空就整行不出）、rejectedEvidence。
- 寫手的 user 訊息**不帶銷售狀態**（`銷售狀態：…` 那行在 Brief 寫手模式拿掉；Product Brief 模型自己的輸入照舊保留）。
- `buyerHesitations` 段名改「可當 FAQ 題材（有才寫）」；`taiwanRisks`／電壓段名改「可當 FAQ 題材：台灣使用」。兩者空就不出。
- 新增一段「款式清單」：清洗後的款式名（去掉【】、+→＋、淘寶贅字如「正版授權」），最多 40 個。給寫手判斷代表角色，也給審稿查角色名。
- 其餘段落（身份、品牌官方英文、IP 官方英文、原型、款式怎麼選、評價重點、台灣常見叫法、已確認事實、差異、情境、粉絲角度、可安全寫入的規格）照舊。

## 3. 程式負責的部分（不靠模型）
### 3.1 描述 HTML 組裝（`htmlFormat.ts`）
- Brief 寫手模式只組 2 段：`<h2>商品介紹</h2><p>…</p>`、`<h2>適合誰</h2><ul><li>…</li></ul>`。舊 4 段格式的測試要同步改。
- 接著是程式產生的「購買前提醒」（只有符合條件才出現，一條都沒有就整段不出）：`<h2>購買前提醒</h2><ul>…</ul>`
  - archetypeFlags 有盲盒／隨機 → `盲盒為隨機出貨，無法指定款式。`
  - Brief 有電壓或 requiresVoltage → `電壓：{voltage}，台灣使用前請確認插頭與電壓。`
  - taiwanRisks 每條原樣一行（最多 2 條）。
- 出貨句：`saleStatusNoticeHtml` 只在銷售狀態＝台灣現貨時加（潮巢語氣那行照舊），其他狀態一律不加。
### 3.2 標題
- 最終標題＝`{品牌/IP 頭}｜{title_item}｜{title_diff}`（沿用 A2 品牌在前契約；title_diff 空就不接）。
- 新增 `dedupeTitleHead(brand, ip, brandEnglish, ipEnglish)`：正規化（去空白、轉小寫）後，若 brand＝ip、brandEnglish＝ipEnglish、brandEnglish＝ip、brand＝ipEnglish 任一成立 → 只留 IP。用在 `normalizeBrief` 的 `fallbackTitleHead` 與最終標題組裝。例：Sanrio／三麗鷗（ipEnglish＝Sanrio）→「三麗鷗」；mofusand／貓福珊迪同理。
- title_diff 若含【】或與某個原始款名完全相同 → 去括號、換成清洗後款名。
### 3.3 SEO
- seo_title：去掉模型自己加的店名後，接「｜潮巢 Nestory」；總長 > 60 字元時，從後往前刪到最後一個「｜／、」分隔處。空或被審稿刪光 → 用現有 `buildTemplateSeo` 的 title。
- meta_description：> 90 字時在最後一個「。！？」截斷；< 30 字或空 → 用 `buildTemplateSeo`，且 `buildTemplateSeo` 改成**在句號處截斷**，不准斷在半句。
### 3.4 自動替換與刪句（免費，不叫模型）
- 全形標點：顧客看得到的所有欄位，「, : ; ! ? ( )」只要左右任一邊是中日韓字元就轉全形；數字之間的逗號、網址、英文詞內部不動。
- 大陸用語直接替換（加進 `MAINLAND_TERMS` 並改成「自動替換」而非只回報）：塑料→塑膠、視頻→影片、屏幕→螢幕、翻轉屏→翻轉螢幕、觸屏→觸控螢幕、概率→機率、信息→資訊、軟件→軟體、充電寶→行動電源、拉鏈→拉鍊、質量→品質、開黑→連線開局。
- 程式直接刪句（寫手欄位：介紹、適合誰、亮點、why、FAQ 答案、seo_description）：含「出貨｜到貨｜代購｜工作天｜預購｜退換｜保固」或「未提供｜無法確認｜未確認｜以實物為準｜商品資料｜標示為」的整句（FAQ 則整題）。
- `SIMPLIFIED_ONLY_CHARS` 刪掉「品」（繁簡同字，害每篇都誤報）。

## 4. 審稿（新階段 review，只刪不加）
- 模型：環境變數 `OPENAI_REVIEW_MODEL`，預設 `gpt-4o-mini`，temperature 0；走既有 textAiEndpoint（OpenRouter 時送 reasoning 設定同寫手規則）。成本記一個 stage `review`。
- 程式先把寫手輸出切句編號（介紹按「。！？」、適合誰每點、亮點每行、why、seo_description 按句；FAQ 按題號），連同事實表（含款式清單、原始標題）送審。
- system prompt（照抄）：
```
你是潮巢的文案審稿員。輸入有「事實表」（含款式清單）和一份文案（每句前面有編號）。你只負責找出要刪的句子，不改寫、不新增。

只有符合下列任一條才刪：
1. 寫了事實表沒有的「可查證事實」：數字、尺寸、容量、材質、內容物、贈品、角色名、品牌名、功能或效果（如降噪、續航、防水、零延遲、穩定、耐用）。
2. 提到出貨、到貨、代購、現貨、預購、價格、退換、保固。
3. 出現「未提供」「無法確認」「以實物為準」「商品資料」「標示」這類說明資料不足的句子。
4. FAQ：整題只是複述規格，或答案和其他欄位講同一件事 → 刪整題。
5. 標題或 SEO 裡出現事實表與款式清單都沒有的角色名或商品名 → 只列出那個詞。

絕對不要刪：畫面、情境、氣氛、比喻、情緒、使用感受、送禮想像、可愛的誇飾。這些是行銷，允許。拿不準就不刪。

只輸出 JSON：{"sentences":[要刪的句子編號],"faq":[要刪的 FAQ 題號],"terms":[{"field":"title|seo_title|seo_description","term":"要拿掉的詞"}]}
```
- 程式執行：只刪編號存在的句子／題目；`terms` 的詞必須原樣出現在該欄位才刪，刪後清掉多餘的「、」「＋」「等」「｜」與空白。審稿回傳壞 JSON、逾時或失敗 → 忽略審稿、照常產出（不阻擋生成），在 cost／checks 記一筆 `review_failed`。
- 審稿後若：亮點剩 < 2 行、商品介紹 < 60 字、適合誰 < 2 點 → 交給 §5 的自動補寫（只補那一欄）。

## 5. 失敗、空欄與自動補寫
- 寫手回傳空內容（例如 `OpenAI response did not include message content`）、或 8 個標記少了 2 個以上（截斷）→ 同模型重試 1 次。再失敗 → 若有設 `OPENAI_COPY_FALLBACK_MODEL` 就用它跑 1 次，否則照舊報錯。
- 允許空的欄位：`title_diff`、`why_we_chose_it`、`generated_faq_html`（0 題時 FAQ 只留固定的聯絡小編文字）、why 空時商品頁不顯示該區（metafield 寫空字串）。
- 不允許空：title_item、商品介紹、適合誰、亮點、seo_title、seo_description（後兩者有 §3.3 退路）。
- 自動補寫沿用 A2 §3.9（一次、只補一欄、不循環），但規則文字改用本規格 §1 對應欄位的規則；`buildChaochaoFieldRegenDescriptionRule` 改成兩段格式。單欄重生（UI 按鈕）在 Brief 模式也用同一套欄位規則。
- `lengthBudget.ts` 不再插進 Brief 寫手提示詞；字數檢查改成：商品介紹 > 260 字、亮點任一行 > 30 字 → 列入自動補寫候選。

## 6. 共用管線（讓盲測＝正式站）
- 把 Brief 寫手模式「寫手 → 程式清理（§3.4）→ 審稿（§4）→ 檢查與自動補寫（§5）→ 組裝（§3.1–3.3）」抽成一個共用函式，`/api/generate` 與 `scripts/copy-a-blindtest.mjs` 的 writer 子程序都呼叫它。盲測拿到的就是正式站會產出的最終文字。
- `scripts/copy-a-blindtest.mjs`：
  - 新旗標 `--review=<model>`（預設 gpt-4o-mini）；`--understand=` 可空（空就不比理解模型，只用 gpt-4o-mini 產共用 Brief）。
  - results.json 每版多存：`finalTitle`、`seoTitle`、`metaDescription`、`descriptionHtml`（最終）、`review`（刪了哪些句、成本）、`stages`（各階段成本）、`retries`。
  - 寫手失敗照舊記 failed、繼續跑（把目前 worktree 裡未 commit 的這個修改一起 commit）。
  - 只讀資料庫，不寫任何東西；輸出到 `--out` 指定的資料夾。

## 7. 測試（`scripts/verify-copy-a.mjs` 新增，全部要過）
1. 「商品」「品質」不算簡體。
2. 全形轉換：「好看,可愛!」→「好看，可愛！」；「1,000」「29×8 cm」「https://a.b/c?d=1」不變。
3. 大陸用語替換：「塑料材質的翻轉屏」→「塑膠材質的翻轉螢幕」。
4. 程式刪句：含「約需 14 個工作天」「資料未提供」的句子被刪，同段其他句保留。
5. `dedupeTitleHead`：Sanrio＋三麗鷗（ipEnglish Sanrio）→「三麗鷗」；VICTOR＋七龍珠 → 「VICTOR × 七龍珠」。
6. 描述組裝：只有商品介紹＋適合誰兩個 h2；盲盒旗標 → 出現購買前提醒「盲盒為隨機出貨」；非台灣現貨不出現出貨句；台灣現貨出現一行。
7. 審稿套用：給定假審稿 JSON（刪句 2、刪 FAQ 1、terms 刪「佐助」），結果正確；不存在的編號與不存在的詞被忽略；壞 JSON → 原文不變並記 review_failed。
8. 審稿後亮點剩 1 行 → 觸發補寫候選 product_highlights。
9. SEO：seo_title 自帶「潮巢」→ 不重複店名；超長截在分隔處；meta 超長截在句號；`buildTemplateSeo` 不再斷在半句。
10. 寫手提示詞：Brief 模式 system prompt 含「兩條線」「[[seo_description]]」，不含「收藏亮點」「3–5 題」「商品資料標示為」「CHAOCHAO_OWNER_VOICE_SAMPLES 的樣板句」。
11. 事實表序列化：不含「仍未知」「未確認」；不含「銷售狀態」；有「款式清單」。
12. 寫手空內容 → 重試 1 次（用假 provider 驗）。
